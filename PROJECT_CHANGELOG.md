### 🏗️ ARCH: граница с `vdx` названа — не всё, что мы придумали, должно ехать отсюда
Правило пользователя, поставленное явно: каждое улучшение в скиле проходит один вопрос ДО написания кода — это **поведение внутри акта** или **утверждение о репозитории**? Второе распространяется через `vdx`, а не через плагин. Причина не вкусовая: плагин живёт внутри одного проекта, ничего не знает про остальные, и у него **нет момента, в который такую проверку можно выполнить** — акт, к которому её привязать, не наступает. Признак, по которому видно, что затея уехала: формулировка начинается с «в каждом репозитории должно быть…» / «проверить, что проект настроил…» / «собрать по всем проектам…». Это не теория: единственный механизм суиты, потребовавший установки, оказался единственным неработающим нигде, и мы измерили его охват неверным методом; проверку унёс `vdx doctor`, и это правильное место, потому что активация — свойство машины и клона, а не репозитория (поэтому даже не ось рубрики). Записано наверху `CLAUDE.md` отдельным разделом, а не шестым Critical Rule: у остальных пяти есть парный детерминированный гейт, а у этого его быть не может — правило про выбор ДО кода, а не про артефакт на диске. Практика на три шага: сформулировать одной фразой → если фраза про репозиторий, отправить постановку агенту `vdx` через intercom и записать решением в кристалле → если гибрид, разрезать по шву (поведение сюда, требование проволоченности туда).
**Ref**: CLAUDE.md (§ «Read second: не всё, что мы придумали, должно ехать отсюда»), docs/model/suite.md (§ История, observed: 2026-09-04)

### 🐛 BUG: сниппет pre-commit-гейта был загейчен на переменную, не заданную ни у кого (vdm-git v2.8.0)
Найдено агентом `vdx` (2026-09-03) при разборе нашей же заявки на ось рубрики — заявку он **отклонил**, и правильно: активация гейта это свойство машины и клона, а рубрика оценивает репозиторий, поэтому проверка ушла в `vdx doctor` (`git-hooks`: объявленные репозиторием хуки обязаны резолвиться end-to-end, «загейчен на незаданную переменную» — именованный отказ со своим remedy). По дороге он проверил три вещи, и все три меняют нашу картину. **(1)** `CRYSTAL_PRECOMMIT_CHECK` не задана нигде на машине — grep по шести профилям и настройкам харнеса; документированный сниппет `[ -n "${X:-}" ] && …` при незаданной переменной схлопывается в no-op, коммит проходит, ничего не печатается. **(2)** `cc-vdm-plugins`, назначенный нами зелёным эталоном, сниппет **не использует вообще** — его `.githooks/pre-commit` закрывает тот же инвариант шестью репо-локальными гейтами. **(3)** Отсюда: наше «1 из 12» посчитано по присутствию файла хука — тем самым методом, недостаточность которого и была предметом заявки; по существу распространяемый механизм собран в **нуле** репозиториев. Проверено здесь заново, всё подтвердилось. Правка: сниппет в `guard/SKILL.md` больше не требует переменной — он резолвит путь сам по **неверсионированной** копии в marketplace-клоне (`…/plugins/marketplaces/*/plugins/vdm-git/scripts/`, глоб покрывает оба корня установки и любое имя маркетплейса; версионированный путь в `cache/<version>/` для этого негоден, сегмент версии двигается на каждом релизе). Переменная осталась как override для CI и нестандартных установок. Установка: три шага → два. И главное — **если резолвинг не удался, сниппет говорит об этом в stderr**: гейт, не нашедший сам себя, не должен выглядеть как гейт, которому нечего сообщить. Обобщение записано в анти-паттерны: *гейт проволочен, когда цепочка резолвится, а не когда его файл лежит на месте.*
**Ref**: plugins/vdm-git/skills/guard/SKILL.md (§ Activating in a downstream project), docs/llm/soft-guidance-vs-deterministic-gates.md (анти-паттерн «Counting a gate as wired because its file is present»), docs/model/suite.md (observed: 2026-09-04)

### 🔧 TOOLING: capture-reminder — красные тесты для хука, который месяцами молчал; prune корня при симлинке в cwd (vdm v2.21.1)
Долг из v2.20.0: фикс ушёл в релиз без единого теста — у `crystal-capture-reminder.sh` покрытия не было ни до, ни после, а закон репозитория гласит, что аудит проверяют на дереве, где есть что аудировать. `tests/crystal-capture-reminder.test.sh` строит проект с активным кристаллом и зовёт хук так, как его зовёт харнесс: cwd = корень, JSON с `session_id` на stdin, `TMPDIR` вынесен **за пределы** наблюдаемого дерева — иначе файл состояния троттлинга, тронутый на emit, сам стал бы «файлом свежее воркайтема», уликой, изготовленной детектором. Главное — **троттлинг доказывается снаружи, а не по пустому выводу**: у «не сканировал» и «убит на скане» вывод одинаково пустой, поэтому подложка `find` первой на `PATH` пишет каждый вызов в журнал, и сигнатура скана — предикат `-newer`; утверждение — «тишина **и ноль сканов**», одна тишина не доказывает ничего. Пары: улика → emit / та же сессия внутри окна → тишина и ноль обходов / другая сессия не затенена; нет улики → тишина, но скан был, и окно не тронуто (первый подходящий промпт срабатывает); единственный свежий файл в `capture-exclude` (с хвостовым `/`, чтобы проверить нормализацию) → тишина, тот же файл без исключения → emit — без второй половины слепой сканер проходит первую; вложенный `node_modules` отсекается по имени; `silent` не сканирует, `proactive` обходит окно; закрытый кристалл — тишина без скана. **Тест сразу нашёл дефект, которого в брифе не было:** корни приходят физическими путями (`git rev-parse --show-toplevel` разыменовывает симлинки), а список prune строился относительно `$PWD`, который может быть логическим (`/tmp` → `/private/tmp`, `/var` → `/private/var` на macOS); при расхождении prune не совпадал, корень кристалла сканировался как исходник, и любой соседний файл под `tasks/` становился уликой. Теперь strip идёт по `pwd -P`, затем по `$PWD`; кейс с симлинком в тесте был красным до правки и зелёный после. Заодно шапка скрипта: обещала state-файл в `vdm-crystal-capture/<session>`, а общий `lib/reminder-throttle.sh` пишет в `vdm-reminder-throttle/crystal-capture-<sid>` — расходилось с момента выноса троттлинга в lib; и «Budget: <5s» уточнён — 15 в `hooks.json` это запас под холодный кэш, не лицензия. Инициировано брифом агента `obsidianvault` через intercom (`crystal-capture-scan-cost`); остальные пункты того брифа — ревью, релиз v2.20.0, подтверждение второго remote — уже закрыты, ручной патч в кэше `2.19.1` мёртв после обновления до 2.21.x.
**Ref**: tests/crystal-capture-reminder.test.sh, plugins/vdm/scripts/crystal-capture-reminder.sh (prune по `pwd -P`; шапка)

### ✨ FEATURE: intercom — справочник агентов; имя, которое говорит человек, доходит с первого раза (vdm v2.21.0)
История, которую закрываем: «а у тебя какое название — `cc-vdm-plugins` или по remote?». У одного этого репо три машинных имени (каталог `cc-vdm-plugins`, слаг `ai-dev-plugins`, `vodmal/ai-dev-plugins`) и **два remote** — рабочий клон на `git.vorobyev.name` и marketplace-клон на GitHub, — из-за чего `register` на каждом запуске ложно кричал о коллизии inbox, а поле `remote` перезаписывал тот, кто регистрировался последним. И ни одного человеческого: пользователь говорит «агент vdm», «агент скилла intercom», а в реестре из 18 записей у восьми `aliases: []`. Отправитель угадывал, `send` на неизвестное имя молча заводил свежий inbox — и бриф, который никто не прочитает, выглядел ровно как доставленный. **Что изменилось.** (1) Реестр стал **справочником**: к `identity` + машинным `aliases` добавлены `names` — имена, которые говорит *пользователь*, `description` — одна строка, по которой тоже ищут, и `remotes[]` — все подтверждённые remote проекта. Регистрация **полная**, когда есть хотя бы одно имя и описание: канонический id и авто-алиасы есть всегда, но их выводит машина, а человек не говорит `vodmal/ai-dev-plugins`. (2) **SessionStart-хук `intercom-identity-check.sh`** (по умолчанию включён, `intercom.identity-check: true` — это не напоминание об inbox, которое остаётся opt-in: он срабатывает один раз при старте и молчит посреди сессии). Механическую часть регистрирует сам, детерминированно; пока нет человеческой — говорит ассистенту завершить её *до остальной работы*: вывести имена из README, названий плагинов/скиллов, каталога, речи пользователя, при неуверенности спросить один раз и не выдумывать. Когда полная — одна строка «you are `ai-dev-plugins` — aka: vdm, intercom, …» плюс счётчик входящих: ответ на «как тебя зовут». (3) **Разрешение имени**: точное совпадение после свёртки (регистр, пробелы/`_` → `-`) по identity/aliases/names одного агента; иначе — *неизвестно* с подсказками (подстрока в именах или в описании: «the intercom agent» находит `ai-dev-plugins` по имени `intercom`) или *неоднозначно*, если имя заявили двое. (4) **`send` на неразрешённый адрес — жёсткий стоп** с подсказками, а не свежий inbox; явный `--first-contact` для действительно нового получателя. **Одно имя → ровно один агент**: `register --name` и `names add` отказывают, если имя уже ведёт к другому, и говорят к какому. (5) Второй remote: реестр не отличит зеркало от коллизии слагов, пользователь отличит — предупреждение держится до `register --same-project` (зеркало) или отдельного `intercom.identity` (другой проект); первичный `remote` больше не перезаписывается. (6) Новые подкоманды `whoami`, `directory` (aka `who`/`list`/`agents`; помечает `⚠ unnamed` и ничейные inbox после first-contact), `resolve`, `names add|rm [--for]`. Порядок имён — порядок ввода, не алфавит (`jq unique` сортирует; первое названное имя — основное). (7) **Негативный сценарий замкнут скриптом, а не памятью.** Вопрос пользователя «а в какой момент хинт станет именем?» показал дыру: запись имени была прозой в SKILL.md, отдельной командой, которую надо не забыть. Теперь момент один и он совпадает с подтверждением: пользователь сказал «это vdm», ассистент пересылает `send "<хинт>" <slug> --to <identity>` — доставка туда, `to_input` хранит хинт, и хинт в той же команде записывается именем получателя. Текст отказа сам называет эту команду и правила: не угадывать получателя, спросить пользователя; случайный хинт («тот, что вчера») не имя — пересылать голым identity, ничего не записывается; хинт, ведущий к *другому* агенту, при `--to` доставляется как велено, но имя не переносится, только подсказка как перенести. (8) **Ничейные inbox после `--first-contact` возвращаются домой.** Отправитель угадал имя, получатель зарегистрировался под другим — письмо лежало в папке, которую никто не читает, и было видно только в `directory`, куда никто не смотрит. Хук старта сессии (и `check`, и `whoami`) сверяет ничейные inbox со своими именами и алиасами по свёртке и предлагает `claim <inbox>`: письма переезжают в канонический inbox, `to:` переписывается на identity, `to_input` остаётся следом, имя записывается. Чужой зарегистрированный inbox `claim` не трогает; ничейный, не совпадающий ни с одним именем, — только с `--force`. **По форме суиты:** сигнал — сравнение двух артефактов на диске (`_registry/<id>.json` против того, что выводится из репо и что говорит человек); мягко, пока имена не названы, — и жёстко на отправке, как только названы. `tests/intercom.test.sh` — 120 проверок против scratch-хранилища: маршрутизация по каждому варианту имени, отказ на опечатку без побочного inbox, неоднозначность, зеркало против коллизии, non-git проект, оба режима хука, `--to` с записью хинта и отказом переносить чужое имя, `claim` с переписыванием конверта.
**Ref**: plugins/vdm/scripts/intercom-common.sh (`names`/`description`/`remotes`, fold, `_intercom_match`, `intercom_registration_missing`, `intercom_remote_mismatch`), plugins/vdm/scripts/intercom.sh (`whoami`/`directory`/`resolve`/`names`/`claim`, `send --to`/`--first-contact`), plugins/vdm/scripts/intercom-identity-check.sh (new, SessionStart), plugins/vdm/hooks/hooks.json, plugins/vdm/skills/intercom/SKILL.md (§ Agent directory, § Session-start identity check), tests/intercom.test.sh (new)

### 📝 DOCS: `suite.md` пересобран под справочник агентов и цену обхода дерева
Дрейф горел по восьми входам (v2.20.0 capture-reminder + v2.21.0 intercom) и погашен в том же рабочем дереве, а не «после коммита». Что изменилось в модели, а не дописано в конец. **(1) Первое долгоживущее состояние суиты — и почему закон его терпит.** Справочник агентов хранит то, чего нет ни в одном файле репозитория: как пользователь называет проект. Второго артефакта для сравнения не существует, поэтому это единственное, что позволено *помнить*; всё выводимое (identity, алиасы, путь) переизводится при каждом старте и вливается, а у каждого невыводимого факта есть названный жест исправления (`names`, `send --to`, `--same-project`). Сигнал дрейфа этого состояния — само использование: неизвестное имя не уходит. Уточнение правила: *помнить можно то, что нельзя вычислить, и только если каждое воспоминание правится одним жестом.* **(2) Валидаторов акта стало два, и найден их общий признак: оба стоят на входе** — `crystal-lint` ловит воркайтем мимо `grow`, `intercom-identity-check` — репозиторий, который ни разу не представился; процедуру не с чего было вызвать, потому что вещь возникла раньше, чем о ней узнали. **(3) Цена сравнения, когда второй операнд — дерево:** дешёвый гейт до дорогой улики, `-prune` вместо `-not -path`, границу дерева объявляет проект (`capture-exclude`); закон о сигнале, прочитанный в обратную сторону. **(4) Девятая строка в таблице подмены области:** хук убит по таймауту, вывод отброшен — молчание неотличимо от «нечего сообщить», и видно только из живой сессии в чужом репозитории. **(5) Снята собственная вторая копия правила:** свёртка имени была реализована и в bash, и в jq — ровно случаи 6 и 8 в третий раз; теперь одна реализация в jq, bash её вызывает, без jq справочника нет вовсе. Ноль правок в `## История` задним числом; три новых пункта археологии с датами.

### 🐛 BUG: the capture reminder was being killed by its own scan (vdm v2.20.0)
Reported from a live session in the `obsidianvault` repo, where the harness had been printing `UserPromptSubmit hook timed out after 5s — output discarded` on essentially every prompt. Measured: `crystal-capture-reminder.sh` took **8.47s** against a declared budget of `"timeout": 5` — so the hook was killed and its output dropped **every single time**, in the one repo where five crystals were active and the reminder had the most to say. Silent in the only way that matters: the hook's failure mode is indistinguishable from having nothing to report. Two causes, and the ordering one is the real bug. **(1) The expensive step ran before the cheap gate.** `smart` mode proves "work happened without capture" by walking the tree for files newer than each active `workitem.md`, and that walk ran on *every* prompt — after which the throttle check would discard the result 9 times out of 10. The window was being enforced on the emit, not on the work; order is now cheap gate → expensive evidence → emit, with the touch still on emit only, so "the first qualifying prompt always fires" is unchanged. **(2) `-not -path` does not skip a subtree, it filters one.** find still descends into every excluded directory and stats every file inside it; `-prune` skips it outright. Same exclusion set, 3.2s → 0.4s on a 35k-note tree. Noise dirs now match by `-name`, so nested `node_modules` are pruned too — previously only the top-level one was. **(3) New: `crystal.capture-exclude`**, an array of project-relative paths, because the standard noise list is a *code* repo's list. A repo whose bulk is content — a note vault, a media archive, a dataset — has tens of thousands of files that are content, not source, and walking them is the entire cost of the hook; no tooling-dir list will ever name them. Absent config = scan everything, which is what a code repo wants. Net on the reporting repo: 8.47s → 2.22s cold, 0.94s inside the throttle window. The declared timeout goes 5 → 15 anyway, as margin rather than as the fix: a hook that only fits its budget on a warm page cache is one slow disk away from the same silence. **The generalization is the suite's own law read backwards.** Every mechanism here is a comparison of two artifacts on disk, and that is cheap precisely because the artifacts are *named*; this one compared a named artifact against **an unbounded set** — "any file, anywhere, newer than this" — and unbounded is where the cost hid. When a detector's second operand is a whole tree rather than a file, the scope has to be declared by the project, because only the project knows which of its subtrees are source.
**Ref**: plugins/vdm/scripts/crystal-capture-reminder.sh (throttle-first ordering, `-prune`, `capture-exclude`), plugins/vdm/hooks/hooks.json (timeout 5 → 15), plugins/vdm/skills/crystal-grow/SKILL.md (§ Configuration)

### 🐛 BUG: the emitted commit command was not self-contained (vdm-git v2.6.0)
Arrived as an intercom brief from `global-auth-gap`, promoted to a crystal. `git-guard-prepare` printed a bare `git commit -F '<msg>'`; the **index is shared per-repository** while the command is written by the assistant and run by the human some time later. With 2–3 sessions in one repo, a neighbour stages its files in that gap and the command sweeps them in — so the contract "the assistant decides what gets committed" was never actually held: the assistant decided only what to *stage*. Now emits `git commit -F '<msg>' -- '<path>'…`, paths from an explicit `-- <path>…` argument or a snapshot of the index. **Three findings changed the shape of the fix.** (1) `git commit -- <paths>` commits the **working tree** version of those paths, and the staged version is then *gone*, not left in the index — for a `git add -p` partial stage that is silent data loss, which is worse than the bug being fixed. So the helper detects `git diff --name-only -- <paths>` ≠ empty and **exits 1** rather than degrading: emitting the pathspec form would lose the hunks, and falling back to the bare form would resurrect the original defect — both silently, exactly when the user had just asked for the opposite. (2) **The brief's own recommendation would have reproduced the bug it warned about.** It asserted `git diff --cached --name-only` returns both sides of a `git mv`; it returns **one** — git collapses the pair to the destination (`R100`), and a commit built from that list leaves the old path in the tree. `--no-renames` is what splits it back into A + D. Caught only because the traps were verified empirically instead of read. (3) Pre-existing, found in the lines being rewritten: `git rev-parse HEAD` on an unborn HEAD prints the literal string `HEAD` to stdout while exiting non-zero, so the `|| echo ""` fallback never fired, the sentinel always matched itself, and every prep leaked a fresh `-N` suffix — `--verify` fixes it. Long lists (>20) switch to `--pathspec-from-file --pathspec-file-nul`, the companion `.paths` file always taking the *same* collision suffix as its message file so two preps cannot cross pairs. Docs updated in lockstep across all four surfaces that reach the assistant — the `UserPromptSubmit` reminder mattered most, since it instructs every agent on every prompt and would have kept describing the old form no matter what the script did. First tests for this helper: `tests/git-guard-prepare.test.sh`.

The interesting part was deciding what *not* to write: `docs/model/suite.md` already carried all three findings **as model** — what happened, and why the mechanisms share a shape — so a new `docs/llm/` page would have been the second copy the repo's own law forbids.
