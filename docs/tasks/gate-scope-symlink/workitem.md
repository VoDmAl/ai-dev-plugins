# Область гейта и симлинки: `abspath` против корней из `git rev-parse`

> Найдено по дороге в `gate-fail-closed-audit` (2026-09-21) и вынесено сюда: это **другой**
> инвариант. Тот кристалл про «гейт не смог запуститься», этот — про «гейт запустился,
> отработал и решил, что файл его не касается». Симптом снаружи одинаковый — тишина, — а
> причина и починка разные.

## Назначение

**Цель.** Сделать так, чтобы принадлежность файла корню кристаллов определялась одинаково с
обеих сторон сравнения, независимо от того, пришёл путь через симлинк или нет.

**Ограничение.** Чинить надо обе реализации предиката сразу: python (`_is_workitem_path` в
`crystal-completion-guard.py`) и bash (`is_workitem_path` в `crystal-lint.sh`). Они — вынужденные
копии (разные входы), поэтому к ним применяется правило конформанса из `docs/model/suite.md`:
одна фикстура, оба движка, тест падает при расхождении.

**Критерий успеха.** Фикстура, лежащая **за симлинком** (`/var/...` → `/private/var/...` на
macOS — то есть обычный `mktemp -d`), даёт тот же вердикт, что и фикстура по реальному пути:
воркайтем со `status: done` и открытым `- [ ]` блокируется в обоих случаях.

## Текущая модель

**Наблюдение (2026-09-21, `Basis: observed`).** Фикстура `mktemp -d` → `/var/folders/.../fx`,
`git init`, воркайтем с открытым чекбоксом, полезная нагрузка с `status: done`, путь в ней —
тот самый `/var/folders/...`. Страж вернул **0** при полностью рабочем окружении (`python3` и
`jq` на месте). Трассировка в том же прогоне:

```
roots:    /private/var/folders/.../fx/docs/tasks
toplevel: /private/var/folders/.../fx
```

**Механизм.** Корни резолвятся через `git rev-parse --show-toplevel` (`lib/crystal-path.sh:215`),
а git возвращает **канонический** путь. Полезная нагрузка несёт путь таким, каким его дал
харнесс. Симулятор берёт `os.path.abspath(file_path)` (`crystal-completion-guard.py`, `main`) —
`abspath` нормализует `..` и относительность, но **не разворачивает симлинки**. Префиксное
сравнение не совпадает ⇒ «не воркайтем» ⇒ `return 0`.

**Почему это до сих пор никого не задело.** Рабочие деревья на этой машине лежат по реальным
путям (`/Users/vdm/...`), и обе стороны совпадают случайно. Задевает там, где проект лежит за
симлинком: `/tmp` и `/var` на macOS, симлинкнутый `$HOME`, рабочее дерево, вынесенное симлинком
на другой том, worktree через симлинк.

**Цена ошибки — ровно та, против которой построена вся суита:** гейт отработал, вернул 0, и
это неотличимо от «нарушений нет».

**Чего не проверено.** Ведёт ли себя bash-предикат (`is_workitem_path` в `crystal-lint.sh`)
так же — по коду он тоже сравнивает строки префиксом, но замера нет. `orphan-guard` уже
канонизирует обе стороны через `cd … && pwd -P` — он, вероятно, здоров, и это тоже не замерено.

## Decision Log

### #1 / 2026-09-21 / Вынесен из `gate-fail-closed-audit` отдельным кристаллом

**Source:** assistant
**Basis:** observed
**Basis-detail:** прогон описан в «Текущей модели»; трассировка корней и `toplevel` снята в том
же окружении, где страж вернул 0. Фикстура красных тестов
(`tests/hook-fail-closed.test.sh`) из-за этого канонизирует путь через `pwd -P` — иначе она
сообщала бы о рабочем гейте как о сломанном.
**Context:** дефект найден при отладке красных тестов fail-closed. Варианты: чинить там же,
записать побегом и забыть, вынести кристаллом.
**Why:** инвариант другой (область против исполнимости), и чинить его надо в двух копиях
предиката сразу, с конформанс-тестом. В коммит про fail-closed это не помещается, не размыв
его собственного доказательства.
**Implication:** `gate-fail-closed-audit` закрывается без этой работы; здесь она заведена в
`ready` и не занимает singleton-слот.
