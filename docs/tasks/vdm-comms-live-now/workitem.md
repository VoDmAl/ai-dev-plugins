# vdm-comms: живой now.md — сборка из домов по владельцу пункта, вместо листа дня

> Бриф hq `live-now-comms` (2026-09-28): решение владельца после грила — лист дня
> `signals/YYYY-MM-DD.md` делится на живой `now.md` (состояние) и датированные новости. Наша часть —
> сборка `now.md` из домов; новости, календарь и строку хука делает echelon. Заведён в `ready`: в
> работе скилл писем.

## Назначение

**Цель** (ТЗ §2, §4, §6). `signals/now.md` собирается из домов проекта (`pending-paths`,
`pending-sections`, «Мои задачи» echelon):
- первая строка — ссылка на инструкцию проекта «как работать»;
- блоки: «твой ход» (владелец пункта — «владелец») · «сегодня и завтра» (от echelon) · «ведёт штаб /
  соседи» (остальные, с датой пересмотра);
- мимо фильтра, сразу в «твой ход» с пометкой «факты собираю»: личные обращения к владельцу, сроки его
  обещаний, исходящее от его имени (черновики `comms/*-out*.md` без `sent:`);
- подъём: пункт соседа с прошедшей датой — в «твой ход»;
- номер пункта — метка блока Obsidian `^id` на строке в доме; `now.md` ссылается `[[файл#^id]]`;
- пересборка без модели; реплики владельца `>> …` в файлах собираются для строки хука echelon.

**Ограничения.** Сразу во всех проектах echelon: hq, command-center, program. Стык с
echelon (календарь, «Мои задачи», счётчики для строки хука) договариваем напрямую.

**Критерий успеха** — приёмка ТЗ §7 в hq, пункты 1–3 и 6: `now.md` из домов с инструкцией в
первой строке; закрытый в треке пункт исчезает после пересборки; просроченный пункт соседа поднят;
реплика `>>` видна сессии первой.

## Текущая модель

Состояние на 2026-09-30:

- **Сборка есть** (vdm-comms 0.13.0, DL #7): `comms-now.sh` пишет `now.md` из домов, с `built` / `your-move`,
  ссылками на `^id` и переносом `>>@ai`. Нет пока: данных echelon, генератора и разметки `^id`, сигнала
  «отстал» — пункты Next actions.
- **Пересборка — команда vdm-comms, хуки не пишут** (DL #1). echelon зовёт её шагом `after_pass`
  проекта; в сессии хук на запись дома говорит «`now.md` отстал», и ассистент запускает команду. В
  `now.md` — время сборки, отставание видно.
- **`^id` ставит сессия** вместе с пунктом; линтер при записи называет пункт без метки; уже открытые
  пункты размечаются один раз командой по слову владельца (DL #2). Формат — буква и две буквы-цифры,
  `a3f`, уникален в проекте (DL #4).
- **Реплики `>>@ai` в `now.md` переживают пересборку** под пунктом с тем же `^id`; пункта нет — наверх,
  «реплики без пункта» (DL #3).
- **Стык с echelon** (DL #5, #6): `echelon soon` / `echelon mine --project <каталог> --json` — форматы
  приняты как есть; `now.md` отдаёт счётчик во frontmatter — `your-move: N`, и `built:` — момент сборки.
- **Владелец пункта называется в проектах по-разному** (замер 2026-09-30, `comms-pending --all --json`):
  hq — `владелец` (8 из 100 открытых), command-center — `владелец` (22 из 355). У program
  `pending-paths` нет. Sidetrack #1.
- ТЗ — `~/AI Projects/hq/docs/tasks/live-now/tz.md`, прочитано целиком 2026-09-30; грил владельца —
  `hq/docs/tasks/signal-intake/references/2026-09-28-sheet-grill.md` (Q4–Q12, Q16–Q19); грил echelon —
  `echelon/docs/tasks/live-now/references/2026-09-29-echelon-grill.md`. Не копировал: живые документы
  соседних репозиториев владельца.

### #2 / 2026-09-30 / `^id` ставит сессия; бэклог — одной командой по слову владельца

**Source:** user
**Basis:** user-stated
**Basis-detail:** владелец 2026-09-30: «Сессия + разовая разметка (Recommended)». Другой вариант:
пересборка сама дописывает `^id` в дома. В вопросе названы числа открытых пунктов — hq 100,
command-center 355 (замер `comms-pending.py --all --json` 2026-09-30).
**Context:** ТЗ §2: «метка блока Obsidian `^id` на строке в доме… поставить, если её нет».
**Why:** метку ставит тот, кто пишет пункт — ход «заполнить поле, а не ловить его отсутствие»; пересборка
остаётся читающей, как и хуки. Линтер при записи называет пункт без метки — обязательство названо в
форме, которую гейт понимает. Бэклог размечается один раз, с диффом, по слову.
**Implication:** элемент линтера «пункт дома без `^id`» (предупреждение), команда разовой разметки,
строка в скилле `pending`: пишешь пункт — ставишь `^id`.

### #4 / 2026-09-30 / Формат `^id`: буква и две буквы-цифры, уникален в проекте

**Source:** assistant
**Basis:** inferred
**Basis-detail:** требования — ТЗ §2 («владелец пишет в чате: „a3f: …“») и правила Obsidian для меток
блока (латиница, цифры, дефис). Не проверялось: как Obsidian ведёт себя с меткой, совпавшей с другим
файлом, — ссылка `[[файл#^id]]` адресует файл, коллизию между файлами исключает уникальность в проекте.
**Context:** бриф hq просит предложить формат: короткий, чтобы писать в чате.
**Why:** три знака — пишется не глядя; первая буква отличает метку от числа — голое число в чате уже
значит ключ задачи без префикса (правило общего слоя о полном ключе). `[a-z][a-z0-9]{2}` — 33 696
значений на проект при 455 открытых пунктах в самом большом.
**Implication:** генератор выбирает случайное неиспользованное в проекте значение; линтер — дубли.

### #3. intercom: `send` подписывает письмо незарегистрированным именем каталога

**Возникло в:** `reply live-now-echelon-commands`, 2026-09-30 — отказ «no agent is registered as "letters"»
**Описание:** письмо echelon пришло с `from: letters`: `send` запустили из каталога `letters` вне
репозитория, и личность взялась из имени каталога. `reply` верно отказал и ничего не записал, но его
текст — отказ `send` с советами про `--to` и `--first-contact`, которые к `reply` не относятся. В хранилище
так подписаны 2 письма: нам и `command-center/live-now-outlook-line`; ответ на второе тоже не дойдёт.
С vdm 2.38.2 такую личность не регистрируют неявно, но `send` по-прежнему ставит её в конверт. Починить
в intercom: отправитель, чья личность держится только на имени каталога и не зарегистрирована, — отказ
до записи; `reply` на письмо с неразрешимым отправителем — свой текст. Отдельным коммитом, red-тесты.

Сделано в vdm 2.39.2. `send` отказывает до записи, если личность держится только на имени каталога, а
каталог не зарегистрирован. Зарегистрированный проект без git и отправка из `$HOME` не тронуты. У `reply`
свой отказ, ничего не архивируется. `tests/intercom.test.sh` +10, на прежнем коде 6 красных.

**Status:** resolved
