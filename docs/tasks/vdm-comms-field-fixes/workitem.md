# vdm-comms 0.4.1: блочный скаляр во frontmatter, молчание вместо «пропущено», counterparts без профиля

## Назначение

**Цель.** Закрыть три полевых отчёта против `vdm-comms`, пришедших 23.09:

- `t23b-program` → `comms-lint-goal-block-scalar`: (1) `goal: |` роняет линтер, хук
  блокирует запись; (2) файл вне контракта даёт пустой вывод, неотличимый от «прошло»;
  попутно — сигнал на старте сессии не называет, что именно отстало.
- `global-auth-gap` → `vdm-comms-0-4-0-acceptance-gag`, пункт 1: старый линтер предупреждал о
  `counterparts` серии без профиля, в 0.4.0 проверки нет.

**Ограничения.** Контракт — пол, не потолок: новых обязательств проектам не добавлять.
Правило `counterparts` — только под уже существующим `meeting-rules.people-profiles`.

**Критерий успеха.** Ни один валидный YAML-блок во frontmatter не превращается в
«cannot read line»; ни один явно названный файл не проходит линтер молча; у старого и
нового линтера `global-auth-gap` одинаковое число предупреждений о профилях.

## Текущая модель

**Воспроизведено 24.09 на дереве отправителя и на синтетике — и дефект шире письма.**
Четыре файла из отчёта на 0.3.0 (`7019fc2`) падают ровно как описано; на 0.4.0 дают `ok` —
но не потому, что починено: 0.4.0 увела исходящие письма (`*/comms/*-out.md`) в отдельную
ветку с построчным чтением, и до строгого парсера они не доходят. Сам парсер блочный скаляр
не читает по-прежнему, и на 0.4.0 падают: файл роли (`agenda.md`), файл серии, входящее
письмо `-in.md` в каталоге встречи. Хук на них — `exit 2`.

Второй дефект тоже жив, в новом облике: исходящее письмо, у которого нечего проверять,
печатает `ok`; явно названный файл вне контракта — пустой вывод и `rc=0`.

`counterparts` у `global-auth-gap`: 32 записи в файлах серий, профили есть у всех — правило
сегодня ничего не поднимет; `meeting-rules` у них пока не включён.

## Decision Log

### #1 / 2026-09-24 / Чинить парсер, а не обходить его ещё одной мягкой веткой

**Source:** assistant
**Basis:** observed
**Basis-detail:** синтетика 24.09: на 0.4.0 `goal: |` в `agenda.md`, в файле серии и в
`-in.md` даёт «cannot read line N»; в `-out.md` проходит только из-за построчного чтения
писем.
**Context:** 0.4.0 уже однажды «вылечила» этот класс, уведя письма от парсера; отчёт от
этого перестал воспроизводиться, а дефект остался.
**Why:** блочный скаляр — обычный YAML, и в `t23b-program` многострочная цель — правило
репозитория, а не случайность. Обход в каждом месте, где встретится, — это N копий одного
пропуска.
**Implication:** `comms_frontmatter.parse` читает `|` и `>` с индикаторами `-`/`+` и цифрой
отступа. Для форм, которых он не знает (многострочное простое значение), ошибка называет
форму и что писать вместо неё.

### #2 / 2026-09-24 / «Пропущено» — явная строка, код выхода прежний

**Source:** assistant
**Basis:** inferred
**Basis-detail:** правило суиты «проверка, которая не выполнилась, обязана это сказать»; у
отправителя то же правило записано в их `CLAUDE.md`.
**Context:** отправитель предложил либо строку `skipped`, либо распространить контракт на все
`comms/`.
**Why:** распространять контракт нельзя — он пол, выведенный из трёх репозиториев, а у писем
треков общего контракта нет. Строка ничего не требует от проекта и убирает неотличимость.
**Implication:** для явно названного файла вне контракта и для письма без проверяемого
(отправлено / ничего не прикладывает) — `<путь>: skipped (<причина>)`. `rc` остаётся 0,
под `--quiet` (хук) строка не печатается, как и `ok`.

### #3 / 2026-09-24 / `counterparts` без профиля — предупреждение, как в старом линтере

**Source:** assistant
**Basis:** observed
**Basis-detail:** `global-auth-gap/.claude/hooks/lint-meetings.py:91-93` — `W.append`, то есть
предупреждение; на их дереве 32 записи, 0 без профиля.
**Context:** приёмка сверяла новый линтер со старым «файл в файл» по числу предупреждений.
**Why:** сделать ошибкой — значит изменить вердикт относительно инструмента, который мы
заменяем, без повода из поля.
**Implication:** под `meeting-rules.people-profiles` файл серии получает предупреждение
на каждого `counterparts` без `<people-dir>/<slug>.md`.

### #4 / 2026-09-24 / Комментарий — не значение: сначала срезать, потом распознавать

**Source:** assistant
**Basis:** observed
**Basis-detail:** сверка всех frontmatter четырёх полевых репозиториев с PyYAML: `ключ:  # …`
читался как значение, равное тексту комментария; `sent: false  # …` — как строка `"false"`;
`people: []  # …` — как строка `"[]"`. Шаблоны встреч `t23b-program` и `global-auth-gap`.
**Context:** в письмах этого не было; нашлось, когда отказ по блочному скаляру починили и
сверку расширили на всю структуру, а не только на изменённые поля.
**Why:** `sent: "false"` читается всеми вызывающими как «значение есть», то есть как
«отправлено» — черновик выпадает из списка неотправленных. Тот же класс, что уже однажды
чинили в `scalar_keys`.
**Implication:** `_strip_trailing_comment` перед любым распознаванием; строка целиком в
кавычках и `#` без пробела перед ним (`https://x/#a`) не трогаются.

### #5 / 2026-09-24 / Вложенность «ключ → список» читать, а не отказывать

**Source:** assistant
**Basis:** observed
**Basis-detail:** первая версия правки честно отказывала на словаре со списками и тем
добавила 18 новых отказов (профили людей `space-hq`, jira-черновики `global-auth-gap`) —
регрессионная сверка «старый против нового» поймала это до коммита.
**Context:** старый парсер эти файлы «разбирал», склеивая подсписки в один список —
неверные данные без единого слова.
**Why:** отказ честнее молчаливой ошибки, но это не исправление; форма — один уровень, и она
живая.
**Implication:** вложенный ключ с пустым значением собирает под собой список скаляров
(глубже ключа или вровень, с комментариями между пунктами). Список словарей на этом уровне —
по-прежнему явный отказ.

## Sidetracks

### #1. Парсер всё ещё расходится с YAML — вне ключей, которые плагин читает

**Status:** resolved (2026-09-24) — граница записана: ни один потребляемый ключ не расходится;
сверка сохранена как `references/yaml-oracle-check.py` (выход 1, если разойдётся)
**Возникло в:** сверка DL #4.

После правки на 3 091 frontmatter остаётся ~53 файла, где значение отличается от PyYAML:
экранированные кавычки внутри `"…"` (`\"` не разворачивается), запятая внутри элемента в
кавычках в `[…]`, wikilink в скобочном списке, формат временных меток. **Ни одно не
приходится на ключ, который читают линтер, индекс или сводка** — проверено поимённо. Чинить
подмножество до полного YAML не входит в предмет; если один из этих ключей станет
потребляемым, первым делом — `python3 references/yaml-oracle-check.py <repo>…` (нужен PyYAML;
только для разработки). Прогон 24.09: 23 / 3 / 26 / 1 расхождений, на потребляемых — 0.
