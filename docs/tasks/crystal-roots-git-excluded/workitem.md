# Кристаллы не видны, когда каталог tasks/ исключён из git (.git/info/exclude, .gitignore)

> Заведён сессией intercom 2026-11-16 по письму агента одного из рабочих проектов владельца (первый из двух дефектов
> письма; второй — [[git-guard-line-consumed-on-other-branch/workitem|git-guard-line-consumed-on-other-branch]]).
> Делает основная сессия владельца: сессия intercom код не правит, рабочее дерево общее. Письмо пересказано, имён
> проектов и людей здесь нет (CLAUDE.md, правило 7); адрес письма — в DL #1.

## Назначение

**Входящее.** Владелец рабочего проекта решил не коммитить его кристаллы и 2026-11-13 добавил `/docs/tasks/` в
`.git/info/exclude`. С этого дня автопоиск корней молчал: `list-open-crystals.sh` ничего не выводил, `crystal-cave.sh`
писал «No crystals found» при трёх активных кристаллах, старт сессии три дня не называл кристалл с двумя просроченными
пунктами. Агент проекта обошёл это явным корнем — `.claude/vdm-plugins.json` → `{"crystal": {"paths": ["docs/tasks"]}}`.

Причина — `_auto_scan_tasks_dirs` в `plugins/vdm/lib/crystal-path.sh` (зеркало — `plugins/vdm-git/lib/crystal-path.sh`):
в git-ветке список берётся из `git ls-files -z --cached --others --exclude-standard`, а `--exclude-standard` выбрасывает
всё, что исключено через `.gitignore`, `.git/info/exclude` и глобальный excludes-файл. Каталог на диске есть, корня нет.

**Готово, когда** кристаллы в `tasks/`, который репозиторий исключил из git, видны автопоиску (или, если решено иначе,
старт сессии прямо говорит, что найденный на диске `tasks/` исключён и не сканируется, и как его включить); красный
тест в `tests/crystal-path.test.sh`; выпуск обоих плагинов (файл зеркальный — CLAUDE.md, правило 3).

## Текущая модель

- Воспроизведено на этой машине 2026-11-16: `git init`, `docs/tasks/x/workitem.md`; до исключения
  `git ls-files -z --cached --others --exclude-standard` даёт 1 путь под `tasks/`, после строки `/docs/tasks/` в
  `.git/info/exclude` — 0. `git ls-files -z --others --ignored --exclude-standard --directory` в том же репозитории
  печатает `docs/` и `docs/tasks/`.
- Обход — явный `crystal.paths`; он у пострадавшего проекта стоит и работает (со слов агента).
- Варианты починки (решает основная сессия, DL #2):
  - **(a) находить и исключённые**: второй вызов `git ls-files --others --ignored --exclude-standard --directory`
    (с `--directory` git не спускается в исключённые каталоги и печатает сам каталог), фильтр — путь кончается на
    `tasks/`, те же отсечения `node_modules`/`vendor`/скрытых сегментов. Не находит `tasks/` под исключённым
    *родителем* (исключён весь `docs/` — печатается только `docs/`); для такого случая — `find` только внутри
    напечатанных исключённых каталогов, с теми же отсечениями.
  - **(b) сказать на старте**, что `tasks/` на диске исключён из git и не сканируется, с командой `crystal-grow paths add`.
    Это детектор там, где поле можно заполнить; см. DL #2.
- Цена (a) не измерена: на дереве с крупными исключёнными каталогами (`var/`, сборки) `--ignored --directory` должен
  оставаться одним проходом без спуска, но это не проверено — меряется запусками процессов, не временем (нагрузка на
  машине).
