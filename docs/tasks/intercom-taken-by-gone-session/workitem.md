# intercom: письмо, взятое закрытой сессией, видно как взятое закрытой

> Вырос из брифа штаба (hq) 29.10 (`sent-taken-by-gone-session`), заведён сессией intercom этого репозитория.
> Сессия intercom код не меняет, поэтому кристалл ждёт основную сессию владельца в `ready`, в пачке с пятью
> кристаллами intercom из заметки `queue-after-letters-pair`. Бриф пересказан, не скопирован; адрес — в References.

## Назначение

Пометку `taken: <машина>/<сессия> <время>` ввёл `intercom-wake-one-machine` (DL #3), чтобы две сессии не делали
одно письмо дважды. Пометку никто не снимает, когда сессия закрывается. Её читают так, будто взявшая сессия жива:

- `sent` у отправителя печатает «taken by … — in work, nobody to wake» (`plugins/vdm/scripts/intercom.sh:1036-1040`),
  и отправитель считает, что работа идёт;
- `check` у получателя печатает «taken by … — leave it to that session» (`intercom.sh:434`), и новая сессия по
  § Receiving письмо не трогает;
- `pickup`, `reply` и побудка тоже обходят письмо, взятое «другой» сессией.

Цепочка застревает, и ни одна сторона этого не видит. Критерий: письмо, взятое сессией, которой нет, в `check`,
`sent` и в отказе `take` названо так и несёт выход — `take --force`; письмо живой сессии выглядит как сейчас.

## Текущая модель

- Дефект наблюдён на двух ящиках этой машины 29.10 (DL #1): у проекта-получателя штаба два письма за сессией,
  закрытой 28.10, и в собственном ящике этого репозитория — `focused-topic-letters` за `cc-vdm-plugins-a0`, которой
  нет среди файлов сессий.
- Проверка жизни взявшей сессии на этой машине — по `sessions/*.json`: имя, живой pid, сокет. Готовый
  `intercom_live_sessions` для неё **не годится как есть**: он пропускает focused-сессии и собственную (DL #2).
- Сессия на другой машине: можно ли по транскрипту связать имя сессии из пометки с её последней активностью, не
  проверено (Sidetrack #1).
- `release --note` «для сессии X» — второй пункт брифа, пока открыт (Sidetrack #2).

## Decision Log

### #1 / 2026-10-29 / Чинить: дефект подтверждён на двух ящиках

**Source:** assistant
**Basis:** observed
**Basis-detail:** 29.10 около 23:35 UTC. Код: `cmd_sent` (`intercom.sh:1036-1040`) читает `taken:` и печатает «in
work» без сверки; `cmd_check` (`intercom.sh:434`) — «leave it to that session». Живые сессии: файлы в
`~/.claude/sessions/` этой машины — у этого репозитория только `cc-vdm-plugins-c6` (сессия intercom) и `cc-vdm-plugins-27`;
`check` при этом отдаёт `focused-topic-letters` сессии `cc-vdm-plugins-a0`. Случай штаба — пересказ брифа: два письма
проекта-получателя взяты его сессией 28.10 в 20:19 UTC, 29.10 в 23:30 UTC живая сессия этого проекта одна, другая;
сам я тот ящик не открывал.
**Context:** бриф просит решить, чинить ли. Альтернатива — снимать пометки руками (`take --force`) по мере находок.
**Why:** руками это видно только тому, кто сверяет пометку с живыми сессиями, а сверять нечем: `check` прямо велит
не трогать. Тот же класс, что «delivered is not received»: состояние на диске выглядит как работа.
**Implication:** правка в `cmd_check`, `cmd_sent`, отказе `take` и, вероятно, в фильтрах `pickup`/`reply`/побудки.

### #2 / 2026-10-29 / Жизнь взявшей — не через `intercom_live_sessions`

**Source:** assistant
**Basis:** inferred
**Basis-detail:** чтение `intercom_live_sessions` (`intercom-common.sh:1457`): `continue` для собственной сессии и для
`mode = focused`. Не проверено прогоном: какую строку `check` выдал бы сейчас для письма, взятого focused-сессией.
**Context:** напрашивается переиспользовать готовый список живых сессий получателя.
**Why:** список строится для побудки — кого будить; focused-сессию будить нельзя, но она жива и письмо держит
законно. Пометка собственной сессии тоже жива по определению.
**Implication:** нужен отдельный предикат «сессия `<имя>` на этой машине жива» поверх тех же полей (pid, сокет), без
фильтров побудки; его же звать из `check`, `sent`, `take`.

## Sidetracks

### #1. Взявшая сессия на другой машине

**Возникло в:** Текущая модель
**Описание:** бриф просит назвать по транскрипту, когда она была активна. `intercom_seen_elsewhere` ищет последнюю
сессию проекта, а не сессию по имени; есть ли имя сессии в транскрипте, не проверено. Если нет — сказать «на другой
машине, отсюда не проверить», а не «in work».

**Status:** open

### #2. `release --note` с адресатом-сессией

**Возникло в:** Назначение (второй пункт брифа)
**Описание:** три письма проекта-получателя отложены с заметкой «для сессии X», где X закрыта. Заметка — свободный
текст; разбирать в нём имя сессии хрупко. Варианты: ключ `release --for <сессия>` с той же проверкой жизни, или
только строка в `check` рядом с отложенным, если заметка называет сессию, которой нет. Решить в работе.

**Status:** open

### #3. `close` не считает письмо, взятое ушедшей сессией

**Возникло в:** перенесён 2026-10-29 из [[intercom-session-name/workitem|intercom-session-name]], Sidetrack #2
(замечен там 28.10 при разборе ящика)
**Описание:** `cmd_close` (`intercom.sh`, функция `cmd_close`) считает в `--waiting <n>` только письма с `taken:`
своей сессии. Письмо, взятое сессией, которой больше нет, следующая сессия intercom оставила бы как есть и закрылась бы
с `--waiting 0`, и число у владельца для письма, которое его всё ещё ждёт, пропало бы. 28.10 обойдено вручную:
`take --force`, после чего `close` его считает. Тот же предикат жизни (DL #2): в `close` считать и письма ушедших
сессий. Тест в `tests/intercom.test.sh`.

**Status:** open
