# Гейты суиты при отсутствии зависимости: аудит fail-open и закон «провалена ≠ не выполнена»

> Вырос из побега `comms-plugin` #1 и решения DL #10 (2026-09-21): класс отказа, ради
> которого затевалась эстафета трёх агентов, обнаружен в собственных гейтах суиты —
> по замыслу. Закрыт в тот же день: замер, починка, красные тесты, закон в синтезе.
> Найденный по дороге дефект области вынесен в `[[gate-scope-symlink/workitem|gate-scope-symlink]]`.

## Назначение

**Цель.** Для каждого **блокирующего** хука `vdm` и `vdm-git` установить наблюдением (не
чтением), что происходит без `python3`, без `jq` и при падении скрипта; привести гейты к
закону «проверка провалена и проверка не выполнена — разные события, для гейта второе тоже
блокирует»; напоминания оставить fail-open. Закон — в `docs/model/suite.md`, тест — красный.

**Ограничение.** Гейт без зависимости не должен блокировать **все** записи подряд: область
хука определяется до вызова зависимости, «не проверено» — только для файлов в области.

**Критерий успеха.** Таблица «хук → без python3 → без jq → при падении» с `Basis: observed`
на каждую клетку; ни один гейт не возвращает 0 или 127 там, где должен 2; `suite.md`
пересобран, дрейф молчит; тест краснеет на возврате к старому поведению.

## Текущая модель

**Замер сделан, гипотеза оказалась мягче реальности** (2026-09-21, `Basis: observed`; метод —
PATH-фарм из симлинков, как `gag` §2 эстафеты; фикстура — `git init` + воркайтем с открытым
`- [ ]` + полезная нагрузка `status: done`):

| Хук | python3+jq | без python3 | без jq | python3 падает |
|---|---|---|---|---|
| `crystal-completion-guard` | 2 | **127** | 2 | **1** |
| `crystal-lint --hook` | 2 | **0** | 2 | **0** |
| `orphan-guard` | 2 | **0** | 2 | **0** |
| `git-guard-hook` | 2 | **127** | — | **1** |

Харнесс блокирует **только на 2**. Значит без `python3` были выключены **все четыре**, а не
один, как предполагал побег. `jq` не влияет ни на один: его отсутствие честно отрабатывается
дефолтами (`lib/config-read.sh`), и это подтверждает, что политика fail-open для *чтения
конфига* верна — ломается не она.

**Починка — `lib/gate-guard.sh` (зеркалируется в оба плагина) плюс правка четырёх хуков.**
`vdm-git` больше не регистрирует хук как `python3 …/git-guard-hook.py`: между харнессом и
гардом встала обёртка `git-guard-hook.sh`. Регистрация вида «интерпретатор + скрипт» делает
интерпретатор частью цепочки доверия, за которой никто не следит.

**Две детали оказались важнее самого правила, и обе найдены на себе:**

1. **Спрашивать надо не про наличие инструмента, а про смысл ответа** (DL #3). Первая версия
   починки проверяла `command -v python3` — и пропускала «`python3` есть и падает»: парсер
   возвращает пустоту, хук читает её как «не моя область», гейт выключен этажом ниже. После
   первого прохода два хука из четырёх всё ещё отдавали 0. Признак, работающий в обоих
   случаях: поле, обязанное быть в нагрузке (`tool_name`), пришло пустым ⇒ нагрузку не
   прочитали.
2. **Область определяется без зависимостей** (DL #4). Префильтр — `grep` по сырой нагрузке,
   его ответ доступен ровно тогда, когда недоступно всё остальное. Без него правило
   вырождается в «на машине без `python3` блокируется любая запись», то есть в гейт, который
   снимут.

**Красные тесты — `tests/hook-fail-closed.test.sh`, 36 проверок**, четыре хука × четыре
окружения (`full`, `nopy`, `nojq`, `crashpy`), и **оба** направления: блокирует внутри
области, молчит вне её. Второе не менее важно: «блокирует, когда не смог проверить» без
«молчит, когда это не его вызов» — это гейт, который удаляют. Седьмой гейт
`.githooks/pre-commit` запускает их при правке любого блокирующего хука плагина или
`lib/gate-guard.sh`.

**Закон записан** в `docs/model/suite.md` → «Четвёртый предел» (там же таблица замера и обе
детали), анти-паттерн — в `docs/llm/soft-guidance-vs-deterministic-gates.md` рядом с
«Counting a gate as wired because its file is present»: это его сосед этажом ниже — не «был
ли гейт проволочен», а «а исполнился ли проволоченный».

**Вне этого кристалла.** Дефект области (`abspath` против корней от `git rev-parse`; за
симлинком гейт молча не применяется) — другой инвариант, вынесен в `gate-scope-symlink`.

## Decision Log

### #1 / 2026-09-21 / Заведён отдельным кристаллом, не внутри ломтя `vdm-comms`

**Source:** user
**Basis:** user-stated
**Basis-detail:** «всё по порядку» — включая пятый кристалл «аудит fail-open гейтов суиты»
из списка хвостов; решение DL #10 `comms-plugin` предписало «аудит — отдельным
кристаллом, не в ломте».
**Context:** можно было чинить гейты `vdm` попутно в `vdm-comms-core`.
**Why:** правка гейтов суиты задевает `lib/` (зеркальный инвариант, оба бампа) и
`suite.md` (пересборка); смешивать с выпуском нового плагина — два риска в одном коммите.
**Implication:** `ready`; порядок относительно ломтей `vdm-comms` — на усмотрение
владельца; закон в `suite.md` нужен **до** 0.1.0, чтобы новый плагин на него ссылался.

### #2 / 2026-09-21 / Замер опроверг побег в мягкую сторону: выключены были все четыре хука

**Source:** assistant
**Basis:** observed
**Basis-detail:** таблица в «Текущей модели». Метод: четыре каталога симлинков на coreutils
как `PATH` (`full` / без `python3` / без `jq` / с `python3`, падающим с трейсбеком), фикстура
`git init` + воркайтем с открытым `- [ ]`, полезные нагрузки собраны отдельным `python3`.
Побег `comms-plugin` #1 называл только `crystal-completion-guard` и был помечен `inferred`
(чтение скриптов).
**Context:** побег фиксирует симптом с гипотезой, а не диагноз (`suite.md` → «Побег фиксирует
симптом, а не причину»); перед починкой его объяснение перепроверяется.
**Why:** гипотеза указывала на один хук — замер дал четыре, и заодно снял подозрение с `jq`,
на который побег тоже косился. Чинить по догадке значило бы починить одну четверть и
«подтвердить» гипотезу.
**Implication:** объём вырос с одного хука до четырёх и затронул `vdm-git`, то есть оба
плагина и зеркалируемый `lib/`.

### #3 / 2026-09-21 / Признак — смысл ответа, а не наличие инструмента

**Source:** assistant
**Basis:** observed
**Basis-detail:** после первой версии починки (проверка `command -v python3`) повторный замер
дал `crystal-lint` → 0 и `orphan-guard` → 0 в окружении `crashpy`. Причина: `python3`
присутствует, парсер вызван, вернул пустоту; хук прочитал пустой `tool_name` как «вызов не
мой» и вышел нулём.
**Context:** напрашивавшийся и уже написанный вариант — спрашивать, установлен ли инструмент.
**Why:** проверка присутствия закрывает машину без инструмента и пропускает машину со
сломанным — то есть ровно тот же класс, что чинится, на этаж ниже. Поле, которое в нагрузке
обязано быть, закрывает оба случая одним условием.
**Implication:** `vdm_have_json_parser` из `lib/gate-guard.sh` удалён как вводящий в
заблуждение; правило записано в шапке библиотеки, в `suite.md` и в анти-паттернах — иначе его
перепишут обратно, потому что «проверить наличие» выглядит очевиднее.

### #4 / 2026-09-21 / Префильтр области — обязательная половина правила, а не оптимизация

**Source:** assistant
**Basis:** observed
**Basis-detail:** в красных тестах восемь из тридцати шести проверок — «GREEN в сломанном
окружении»: запись исходника, воркайтем без терминального статуса, обычный markdown, обычная
команда Bash. Без префильтра каждая из них блокировалась бы.
**Context:** соблазн реализовать закон как «нет зависимости → exit 2» одной строкой.
**Why:** гейт, блокирующий всё на машине без `python3`, снимают — а снятый гейт равен
отсутствующему (`suite.md`: «врущий в обе стороны хуже отсутствующего»). Префильтр обязан
быть беззависимостным (`grep` по сырой нагрузке), иначе он недоступен ровно тогда, когда нужен.
**Implication:** у каждого хука свой префильтр, приближённый и узкий: страж завершения —
только терминальный статус в воркайтеме; линт — запись воркайтема; orphan-guard — `docs/llm/`
или `covers:`; git-guard — Bash с `commit`/`push`. Оба направления зафиксированы тестом.

### #5 / 2026-09-21 / Красные тесты — отдельный файл и отдельный (седьмой) гейт, не внутри `gates.test.sh`

**Source:** assistant
**Basis:** inferred
**Basis-detail:** выведено из устройства `tests/gates.test.sh`: он материализует рабочее дерево
в клон и проверяет гейты **этого репозитория** (`scripts/check-*.sh`, pre-commit). Новые тесты
проверяют **хуки, уезжающие в плагине**, и им нужен не клон, а PATH-фарм. Совместимость
запуска в одном файле не проверялась — решение принято по разнице предметов, а не по замеру.
**Context:** план кристалла говорил «`tests/gates.test.sh`: красные тесты».
**Why:** разные предметы и разная цена (15 с против 5 с), а условие запуска шестого гейта —
«застейджен гейт репозитория» — на правку хука плагина не срабатывает. Внутри одного файла
пришлось бы либо платить 15 с за правку хука, либо усложнять условие.
**Implication:** отклонение от плана кристалла зафиксировано здесь; `.githooks/pre-commit`
получил седьмой гейт со своим условием; `suite.md` и README описывают их как пару с разными
предметами.

## Sidetracks

### #1. `crystal-lint --staged` в pre-commit наследует ту же слабость, но безвредно

**Status:** resolved — проверено при правке: pre-commit трактует любой ненулевой код как отказ,
поэтому падение линтера там блокирует коммит, а не пропускает его. Отдельная починка не нужна;
текст отказа остаётся техническим (код 127 без пояснения) — это косметика, не дыра.
