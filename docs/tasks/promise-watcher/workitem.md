# Сторож обещаний в разговоре: обещание без записи в файл — напомнить в том же ходу

> Заведён сессией intercom 2026-10-30 по письму echelon `promise-watcher`. Делает основная сессия владельца: это
> новый хук, а сессия intercom код не правит — рабочее дерево общее. Письмо пересказано, адрес — в DL #1.

## Назначение

**Входящее.** Echelon строит у себя модель «что висит»: штаб завязывает нить в момент обещания, echelon показывает
свободные концы. Но echelon видит только механические концы — письма, задачи, мячи intercom. Обещание, прозвучавшее
в разговоре, ловит только сессия, где оно прозвучало: транскрипты на обещания echelon не читает. Слово владельца
29.10, переданное echelon, — против чего это всё: *«если я что-то не сделал потому что забыл или потерял в истории
переписки с тобой (для этого кстати делали кристаллы, чтобы ничего не терялось и wrap для этого же) - то это кого-то
подвело, меня подвело»*. Случай echelon 28.10: агент пообещал «отправлю итог, когда другой штаб ответит», и это
обещание в разговор не вернулось.

**Просьба.** Хук на конец хода, по образцу `crystal-grow-nudge`:
- за ход в тексте ассистента или в реплике владельца есть обещание — срок, «сделаю», «отправлю», «когда X — то Y»;
- и этот ход ничего не записал в файл верёвки — кристалл, трек, леджер;
- тогда один раз напомнить завязать нить.

Как узнавать обещание — решаем мы; echelon допускает суждение модели: это сессия, а не его сбор.

**Критерий успеха.** Обещание, данное в ходе и не записанное, получает напоминание в том же ходу; обещание,
записанное тем же ходом (в том числе через Bash), — не получает.

## Текущая модель

- **Мягкое правило уже есть.** Общий слой правил машины (`~/.claude/vdm/rules.md`, раздел «A correction reaches every
  copy; lasting work gets its file first») требует, чтобы обещание с датой жило в файле работы, а обязательство
  владельца шло тем же ходом по intercom в список штаба (раздел «The user's obligations go to HQ»). Просьба — заслон
  на Stop там, где правило не сработало.
- **Образец есть.** `plugins/vdm/scripts/crystal-grow-nudge.sh` (late-grow DL #4, #5): тест формы по
  `last_assistant_message`, транскрипт читается только на ранние записи в workitem, раз за разговор, через
  `additionalContext`. Его полевые цифры — первая мерка будущего ложного срабатывания: 22 подсказки на 91 сессию, три
  ложных из-за записи workitem через Bash, все срабатывания «на одних шагах» отвечали отчёту.
- **Две половины условия разной природы.** «Ход записал в файл верёвки» — механика: вызовы инструментов хода против
  объявленных домов (корни кристаллов, дома `pending` из конфига vdm-comms) плюс отправка по intercom. «В ходе
  прозвучало обещание» — суждение о тексте; на диске его второй стороны нет, и это первый механизм суиты, у которого
  сигнал не сравнение двух артефактов (`docs/model/suite.md`) — `crystal-grow-nudge` тоже тест формы текста, но
  формы, а не смысла.
- **У обещания два хозяина и два дома.** Обещание ассистента — в Next actions кристалла (`(due:)`, `when:`).
  Обещание владельца — не в этот репозиторий, а письмом штабу (правило слоя). Значит «записал» должен засчитывать и
  `intercom send` штабу, иначе сторож будет напоминать о верно отправленном.
- Это поведение внутри акта (конец хода), а не утверждение о репозитории — место в плагине, не в `vdx`.

подкрепляет.
**Implication:** echelon получает частичный итог сейчас (`reply`), окончательный — письмом
