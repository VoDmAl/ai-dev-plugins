# Бриф executor `git-syncthing-split` (2026-10-01) — пересказ

Пересказ, а не копия: в оригинале имена и идентификаторы машин владельца, репозиторий публичный. Оригинал — в
intercom-хранилище, `ai-dev-plugins/_done/git-syncthing-split.md` после pickup. Тот же бриф ушёл `echelon`;
владелец, дословно: «Передай фактуру проблемы в vdm skill + echelone пусть подумают вместе как быть».

## Устройство

- Репозиторий executor лежит в папке Syncthing (`sendreceive`) вместе с `.git`; папку делят три устройства
  владельца. `.git` в `.stignore` не исключён — как и у остальных репозиториев этой папки.
- В тот вечер сессии в этом репозитории работали на двух машинах одновременно.

## Что случилось (2026-10-01, EDT)

1. 18:42:32 — на машине A закоммичен `ecf4f2db` (родитель `406dcd2d`), сразу запушен на оба remote.
2. 18:44:32 — на машине B закоммичен `c31f4703` тоже на `406dcd2d`: ссылка с A туда ещё не доехала.
3. Syncthing оставил версии B для `refs/heads/master`, `logs/HEAD`, `logs/refs/heads/master`, `COMMIT_EDITMSG`,
   `index`; версии A легли рядом копиями `*.sync-conflict-*` (в копии ссылки — `ecf4f2db`).
4. Объект `c31f4703` приехал на A примерно через 15 минут после ссылки: в 18:47 `git cat-file` его не находил, в
   18:59 — находил. Всё это время HEAD на A не читался, `git diff --cached` показывал всё дерево добавленным.
5. 18:59:53 — простой `git status` на A переписал `.git/index`, и Syncthing тут же сделал новую копию индекса.

## Что сработало и что нет

- `git-guard-prepare` увидел копии и отказался готовить коммит — это остановило беду.
- Подсказка в отказе вводила в заблуждение: «branch master no longer exists; recover it: git branch <name>
  ecf4f2db» и строка `fatal: git show-ref: bad ref refs/heads/master (c31f47…)`. Ветка была — она указывала на
  ещё не доехавший объект. Файл копии ссылки git к тому же видит как отдельную ветку.

## Как починили (на машине A, когда сессия на B закончила)

Копии вынесены из `.git` с резервной копией; проверено, что два файла `c31f4703` в рабочем дереве совпадают с
коммитом; `git reset -q origin/master`; `git commit -C c31f4703 -- <два файла>` — коммит с исходным сообщением,
автором и датой. Ничего не потеряно.

## Вопрос к ai-dev-plugins и echelon

Как сделать, чтобы две машины с одновременными сессиями не разрывали `.git`. Варианты автора — гипотезы, не
решения: не синкать `.git` (свой клон на машину, обмен через remote); оставить синк, но общий для машин сигнал
«здесь идёт работа с git» (кто его держит — echelon видит больше одной машины?); проверка при старте сессии и перед
коммитом — копии в `.git` и существует ли объект HEAD, с понятной подсказкой; `GIT_OPTIONAL_LOCKS=0` для всех
чтений git из хуков **и агентов**. Договориться между собой и вернуться к владельцу с предложением.
