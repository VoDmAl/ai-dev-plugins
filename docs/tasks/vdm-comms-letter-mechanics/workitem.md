# vdm-comms: механика файла письма — что из CLAUDE.md проектов ещё не в плагине

> Перенесено из `[[vdm-comms-letters/workitem|vdm-comms-letters]]`, Sidetrack #4. Тот кристалл делал скилл
> о **содержании** письма и механику файла сознательно не трогал (его DL #7). Здесь — механика: где лежит
> файл письма, как он называется, какие у него поля и ссылки. Вход — 31 кластер `comms-mech` (К86–К116)
> из синтеза program.

## Назначение

**Цель.** Каждый кластер К86–К116 получает место: правило в скилле (`meetings`, раздел «Outgoing letters»,
или `letters`), проверку в линтере там, где она механически возможна и заслужена, — или явное «остаётся в
проекте» с причиной. Решение владельца «выносим всё общее, одиночные общие тоже» (`vdm-comms-letters`
DL #2, первоисточник — executor `claude-md-slimming` DL #5) покрывает и механику.

**Ограничения.** Сначала мягкое правило, гейт — когда заслужит
(`docs/llm/soft-guidance-vs-deterministic-gates.md`). Готовое в плагине не переписывать. Сверку почтового
ящика (К113) не брать — она в `[[vdm-comms-mail/workitem|vdm-comms-mail]]`.

**Критерий успеха.** У каждого кластера из списков ниже есть адрес или причина остаться в проекте; executor,
command-center и hq знают, что из своих CLAUDE.md они могут снять.

## Текущая модель

Состояние на 2026-09-30 — сверка синтеза с плагином (vdm-comms 0.16.1) и замер по трём проектам:

- **Уже в плагине:** К91–К93 (пометка черновика, `sent:` только правкой — vdm-comms 0.6.6 и
  `vdm-comms-letters` DL #3), К95 (имя файла), К96 (сырой `.eml`), К98 и К100 (раздел 📎, линтер резолвит
  ссылки), К87 (черта `separator`, opt-in), К102 частично (`Subject` обязателен для email).
- **В другом кристалле:** К113 → `vdm-comms-mail`.
- **Общие (два-три проекта), в плагине нет:**
  - К94 — дата в имени файла = день отправки (executor, gag, hq). Расхождений: gag — 6 из 246 писем с
    датой в `sent:` (например, `incidents/address-add-panics-on-db-error/comms/2026-09-25-golubev-telegram-out.md`
    при `sent: 2026-09-29`); hq — 0 из 60; executor — 0 из 18 (остальные 173 его письма пишут
    `sent: true` без даты, сравнивать не с чем).
  - К86 — сначала файл в `comms/`, потом текст в чат (три проекта).
  - К107 — файл = отправленное: отправлено с правками — сначала файл под отправленное, потом `sent:` (gag,
    hq).
  - К97 частично — входящее текстом в `comms/` своего трека, дата — дата письма (три проекта; место
    `-in.md` в плагине есть, правила о дате нет).
  - К103 (обратная ссылка `> Ответ на:`), К104 (шапка `# → Имя` / `# ← Имя`), К105 (строка в таблице
    переписки `index.md`), К106 (`comms/` — сырьё), К108 (состояние — из файла письма, не из записи о нём).
- **Одиночные:** К88, К89, К90 (hq); К99, К101, К109, К110, К111, К112, К114 (executor); К115, К116 (gag).
- **К109 держится на непроверенной посылке.** Правило: «`track:` во frontmatter совпадает с папкой». В
  executor `track:` есть в 146 исходящих, и в 56 из них последний сегмент значения не встречается в пути
  письма. Например, `program/2026-2027/court-of-honor-september/comms/2026-09-08-doe-reply-out.md` с
  `track: program/2026-2027/alpine-skills` и `…/court-of-honor-september/comms/2026-09-12-planning-conference-out.md`
  с `track: meetings/2026-09-14-first-troop-meeting`. Похоже, у них `track:` — «о чём письмо», а не «где
  лежит»; что поле значит, у executor не спрошено. Сравнение грубое (сегмент против пути), разобрано глазами
  только на двух примерах.
- **«Разбор = применение» — правило есть, проверки нет.** Скилл `letters` § 13: каждое «отметить /
  закрыть» в разборе несёт ✅ или ссылку туда, где припарковано. У executor это держит Stop-хук
  `scripts/check-inbox-applied.py` (с 2026-09-27): входящее с `direction: in`, тронутое за 12 часов, строка
  «Разбора» с глаголом действия без ✅ и без `[[ссылки]]` — ход не закрывается, один раз. Перенести его как
  есть нельзя — он держится на форме, которая есть только у executor:

  | | executor | command-center | hq |
  |---|---|---|---|
  | входящих (`-in.md`) с «Разбором» | 91 из 168 | 27 из 174 | 9 из 35 |
  | где разбор | в письме: `## Разбор` или `> **Разбор DD.MM:**` | чаще в notes: `> Разбор — [[../notes…]]` | так же, в notes |
  | `direction: in` во frontmatter | 148 | 75 | 0 |
  | `processed:` (К112) | 148 из 172 | 0 | 0 |

  Сам хук executor видит только форму `> **Разбор…:**`: на `## Разбор` сканирование кончается на пустой строке
  под заголовком (проверено вызовом их `pending()` 2026-09-30).
