# vdm-comms: механика файла письма — что из CLAUDE.md проектов ещё не в плагине

> Перенесено из `[[vdm-comms-letters/workitem|vdm-comms-letters]]`, Sidetrack #4. Тот кристалл делал скилл
> о **содержании** письма и механику файла сознательно не трогал (его DL #7). Здесь — механика: где лежит
> файл письма, как он называется, какие у него поля и ссылки. Вход — 31 кластер `comms-mech` (К86–К116)
> из синтеза program.

## Назначение

**Цель.** Каждый кластер К86–К116 получает место: правило в скилле (`meetings`, раздел «Outgoing letters»,
или `letters`), проверку в линтере там, где она механически возможна и заслужена, — или явное «остаётся в
проекте» с причиной. Решение владельца «выносим всё общее, одиночные общие тоже» (`vdm-comms-letters`
DL #2, первоисточник — executor `claude-md-slimming` DL #5) покрывает и механику.

**Ограничения.** Сначала мягкое правило, гейт — когда заслужит
(`docs/llm/soft-guidance-vs-deterministic-gates.md`). Готовое в плагине не переписывать. Сверку почтового
ящика (К113) не брать — она в `[[vdm-comms-mail/workitem|vdm-comms-mail]]`.

**Критерий успеха.** У каждого кластера из списков ниже есть адрес или причина остаться в проекте; executor,
command-center и hq знают, что из своих CLAUDE.md они могут снять.

## Текущая модель

Состояние на 2026-09-30 — сверка синтеза с плагином (vdm-comms 0.16.1) и замер по трём проектам:

- **Уже в плагине:** К91–К93 (пометка черновика, `sent:` только правкой — vdm-comms 0.6.6 и
  `vdm-comms-letters` DL #3), К95 (имя файла), К96 (сырой `.eml`), К98 и К100 (раздел 📎, линтер резолвит
  ссылки), К87 (черта `separator`, opt-in), К102 частично (`Subject` обязателен для email).
- **В другом кристалле:** К113 → `vdm-comms-mail`.
- **Общие (два-три проекта), в плагине нет:**
  - К94 — дата в имени файла = день отправки (executor, command-center, hq). Расхождений: command-center —
    6 из 246 писем с датой в `sent:` (например, имя от 25.09 при `sent:` 29.09); hq — 0 из 60; executor — 0 из
    18 (остальные 173 его письма пишут `sent: true` без даты, сравнивать не с чем).
  - К86 — сначала файл в `comms/`, потом текст в чат (три проекта).
  - К107 — файл = отправленное: отправлено с правками — сначала файл под отправленное, потом `sent:`
    (command-center, hq).
  - К97 частично — входящее текстом в `comms/` своего трека, дата — дата письма (три проекта; место
    `-in.md` в плагине есть, правила о дате нет).
  - К103 (обратная ссылка `> Ответ на:`), К104 (шапка `# → Имя` / `# ← Имя`), К105 (строка в таблице
    переписки `index.md`), К106 (`comms/` — сырьё), К108 (состояние — из файла письма, не из записи о нём).
- **Одиночные:** К88, К89, К90 (hq); К99, К101, К109, К110, К111, К112, К114 (executor); К115, К116 (command-center).
- **К109 верно для писем людям, неверно для канала агентов** (DL #3). В executor `track:` значит «о чём
  письмо», и в письме человеку оно обязано совпадать с папкой — их `CLAUDE.md`, § «Письмо лежит там, о
  чём оно, а не там, где начался тред». Исключение — `docs/comms/`: там письма соседним агентам, папка —
  канал, `track:` указывает на тему. Счёт по префиксу (`track:` — префикс папки письма или наоборот): у
  146 исходящих с `track:` расходятся 49; 45 из них в `docs/comms/`, 4 — дрейф, признанный executor (тред
  уехал, файл остался): письмо лежит в `comms/` одного трека, а `track:` называет встречу из другого. Проверка К109 без знания канала агентов срабатывала
  бы на каждое письмо агенту.
- **«Разбор = применение» — правило есть, проверки нет.** Скилл `letters` § 13: каждое «отметить /
  закрыть» в разборе несёт ✅ или ссылку туда, где припарковано. У executor это держит Stop-хук
  `scripts/check-inbox-applied.py` (с 2026-09-27): входящее с `direction: in`, тронутое за 12 часов, строка
  «Разбора» с глаголом действия без ✅ и без `[[ссылки]]` — ход не закрывается, один раз. Перенести его как
  есть нельзя — он держится на форме, которая есть только у executor:

  | | executor | command-center | hq |
  |---|---|---|---|
  | входящих (`-in.md`) с «Разбором» | 91 из 168 | 27 из 174 | 9 из 35 |
  | где разбор | в письме: `## Разбор` или `> **Разбор DD.MM:**` | чаще в notes: `> Разбор — [[../notes…]]` | так же, в notes |
  | `direction: in` во frontmatter | 148 | 75 | 0 |
  | `processed:` (К112) | 148 из 172 | 0 | 0 |

  Сам хук executor видит только форму `> **Разбор…:**`: на `## Разбор` сканирование кончается на пустой строке
  под заголовком (проверено вызовом их `pending()` 2026-09-30).

Сделано 2026-10-14 (vdm-comms 0.32.0, DL #4, #5):

- **`meetings` → *The letter file is the record***: файл первым, чат — потом (К86); каждая правка — в файл,
  отправленное с правками — сначала файл, потом `sent:` (К107); состояние — из файла, запись о письме несёт
  ссылку (К108); письмо — в `comms/` трека, о котором оно, канал агентов — своя папка (К109); дата в имени —
  день отправки (К94); обратная ссылка в шапке или `reply-to:` (К103); `# →` / `# ←` (К104); строка в таблице
  переписки, где она есть (К105); снятый черновик удаляется (К110); письмо — средство, дело — свой пункт (К111).
- **Входящее**: в `comms/` своего трека, дата — дата письма, шапка `# ← <имя>` (К97, К104); текст как прочитан,
  наш комментарий — рядом и помечен (К106).
- **Форма**: ниже черты — без разметки, которой канал не покажет (К88); несколько сообщений — `## Message N` (К89);
  вложение лежит там, где его предмет, `attachments/` — когда другого места нет (К99).
- **Замер 2026-10-14**, только счёт, `*/comms/*-out.md` и `-in.md` трёх проектов:

### #3 / 2026-10-01 / К109: `track:` — «о чём», совпадает с папкой в письмах людям; канал агентов — исключение

**Source:** both
**Basis:** observed
**Basis-detail:** ответ program 2026-10-01 (`ai-dev-plugins/_done/check-inbox-applied-transfer-outcome`)
сверен с их файлами в тот же день: правило — `~/AI Projects/program/CLAUDE.md`, строка 541, § «Письмо
лежит там, о чём оно, а не там, где начался тред»; пересчёт по префиксу — 146 исходящих с `track:`, 49
расхождений, 45 в `docs/comms/`, 4 дрейфа (те же четыре файла, что в их письме). Не копировал: правило и
письма живут в соседнем репо; адрес и счёт выше.
**Context:** в «Текущей модели» стояла догадка «у executor `track:` — о чём письмо, а не где лежит», и первый
пункт Next actions спрашивал об этом. Мой первый счёт (56) сравнивал последний сегмент с путём и был грубее.
**Why:** догадка оказалась верной наполовину: «о чём» — да, но в письме человеку «о чём» и «где лежит» обязаны
совпадать, так что К109 стоит. Неверна она для писем агентам — там папка обозначает канал. Проверка без этого
исключения срабатывала бы на каждое письмо агенту.
**Implication:** К109 — кандидат в линтер с исключением для канала агентов. Как опознавать канал — решить при
работе: папка (`docs/comms/` у executor) или `channel: intercom` в письме (скилл `letters` § 14); есть ли такой канал
у command-center и hq — проверить там же.
