# Исходящий текст без разметки: проверка черновика по каналу

> Бриф агента одного из проектов владельца (intercom, 2026-11-12): письмо для почты ушло
> в «Черновики» с жирными заголовками и ссылками Markdown, линтер ответил `ok`. Правило
> в навыке есть, проверки нет. Заведено сессией intercom: код — для основной сессии.

## Назначение

Черновик с `channel:` вне `comms.markdown-channels` не должен нести под разделителем
`---` разметку, которую его канал не показывает: этот текст уходит в канал как есть, и
получатель видит решётки, кавычки и скобки. Цель — сравнение того же устройства, что уже
держит жёсткие переносы (`outgoing-text-unwrapped`): конструкции под разделителем против
того, что канал показывает (DL #3), и находка с номерами строк. Плюс строка в памятке при
рождении черновика, чтобы такая разметка не появлялась вовсе.

Критерий (с поправкой DL #3 к критерию брифа): черновик `channel: email` со строкой
`# Цель` под разделителем даёт находку с номером строки, со строкой `**Цель**` — нет
(почта через echelon показывает жирный); `# Цель` в `channel: intercom` — нет.

## Текущая модель

- Правило записано: `plugins/vdm-comms/skills/meetings/SKILL.md`, элемент `separator` в
  таблице `comms.letter-form` — «everything below the line is pasted as it stands, so it
  carries no quote marks, bold or other markup the channel will not show».
- Проверки нет: `plugins/vdm-comms/scripts/comms-lint.py` для черновика проверяет
  наличие разделителя (`_lint_letter_form`) и жёсткие переносы (`_lint_unwrapped`, по
  `comms.markdown-channels`, по умолчанию `intercom` и `gitlab`). Разметку под
  разделителем не смотрит никто.
- Навык `letters` § 2 «The channel» говорит о форме письма и об «one paragraph is one
  line», о разметке — ничего.
- **Канал показывает не «всё или ничего», а набор конструкций** (DL #3). Почта, которую
  собирает echelon (единственный путь почты у проектов владельца), с 2026-10-04 уходит
  двумя частями — text/plain и HTML из одного текста; Gmail открывает HTML. В HTML парные
  `**жирный**`, `*курсив*`, `***оба***` — настоящие `<b>`/`<i>`, каждый перевод строки —
  `<br>`. Сырьём остаются ссылки `[…](…)`, строки-заголовки `#`, обратные кавычки.
- Значит, для почты находка — `#`, обратные кавычки и ссылки `[…](…)` не на веб-адрес;
  жирный, курсив и `[текст](https://…)` — не находка. Владелец сам пишет жирным в письмах
  и просил этого — ради этого echelon и сделал HTML.
- **Ссылки на веб-адрес почта показывает с 2026-11-13** (коммит echelon `5244f5b` в main,
  его кристалл `letter-body-markup` DL #2; письмо `echelon-email-links-real`). В HTML
  `[текст](http…)` — настоящая ссылка, в text/plain — «текст (адрес)», а если текст и есть
  адрес — один адрес. Ссылкой становится только то, что берёт `ownerword.LINK` в его коде:
  `\[([^\]\n]+)\]\((https?://[^\s()<>]+)\)`. Ссылка на файл, `mailto:` и адрес со скобками
  или пробелом остаются сырьём — это находка. Прочитано здесь в `runtime/echelon/mail.py`
  (`to_html`) и `ownerword.py` (`LINK`, `plain_links`). Оговорка echelon: сессия, чей
  MCP-сервер запущен до коммита, кладёт черновик старым кодом до `/mcp` → Reconnect (сервер
  говорит «отстал на N правок»), и ссылка сырьём в таком черновике — не ошибка линтера.
- **У echelon копия нашего контракта письма.** Его хук ключей (`runtime/echelon/keylinks.py`,
  тот же коммит) в файле с `channel:` вне `comms.markdown-channels` не ставит ссылки на
  задачи в текст под первым разделителем после frontmatter, а без разделителя — во всё
  тело. Граница повторяет `comms_unwrap.outgoing`, список — умолчание
  `MARKDOWN_CHANNELS = ("intercom", "gitlab")` плюс список проекта из
  `comms.markdown-channels`, как `comms_config.py`. Сменим умолчание `markdown-channels`
  или границу текста письма — echelon узнаёт об этом письмом (его просьба, наш мяч).
- Проверка переносов для почты остаётся верной: перевод строки в HTML — `<br>`, абзац,
  свёрнутый в редакторе, приходит разорванным.
- **Zulip** (`zulip_send`) показывает Markdown как intercom и GitLab: echelon отдаёт
  текст байт в байт, разметку переводит сервер Zulip. По прогону echelon через рендер
  сервера без отправки (12.11) видны `**жирный**`, `*курсив*`, `~~зачёркнутый~~`,
  ссылки `[…](…)`, заголовки `#`, обратные кавычки, списки `- `; сырьём остаётся только
  `__подчёркивание__`. Одиночный перевод строки внутри абзаца Zulip показывает разрывом
  строки, не склеивает (рендер echelon 14.11), поэтому `zulip` вне
  `comms.markdown-channels`: жёсткие переносы для него — находка, как для почты (DL #4).
- **Telegram** (`tg_send`, `tg_draft`) не показывает ничего: echelon кладёт текст сырым
  запросом MTProto, одним `message` без `entities`, и разбор разметки Telethon на этом
  пути не работает. Получатель `tg_send` видит `**`, `*`, `[…](…)`, `#` и обратные
  кавычки как есть. Черновик `tg_draft` ложится в поле ввода владельца тем же сырым
  текстом; превратит ли приложение владельца `**…**` в жирный при отправке, echelon не
  проверял (Sidetrack #5).
- Источник двух пунктов выше — письмо echelon `echelon-tg-zulip-render-markup`
  (2026-11-12), по его коду (`zulipsend.Send.send`, `tgsend.deliver`). Здесь не
  перепроверено: у этого проекта `zulip_send` и `tg_*` закрыты.
- О том, что показывает канал, говорит echelon (его слово 12.11: «Говорю я: черновики
  почты собирает echelon»), не конфиг каждого проекта.

### #4. Zulip — в `comms.markdown-channels` по умолчанию или нет

**Возникло в:** письмо echelon `echelon-tg-zulip-render-markup`, 2026-11-12
**Описание:** echelon оставил решение нам. Разметку Zulip показывает, но список
`comms.markdown-channels` снимает **обе** проверки — и разметку, и жёсткие переносы
(`_lint_unwrapped`). Внести `zulip` в список по умолчанию верно, только если Zulip ещё и
склеивает строки одного абзаца. Как Zulip показывает одиночный перевод строки, письмо не
говорит, а здесь это не проверено. Если он ставит разрыв строки, `zulip` остаётся вне
списка, а его набор «показывает всё, кроме `__…__`» живёт в наборах по каналу (DL #3).
Проверить может только echelon, тем же рендером без отправки. Спросить из основной
сессии: эта сессия intercom упёрлась в предел цепочки — три звена подряд из сессий
intercom. Внести `zulip` в умолчание — значит сменить умолчание, копию которого держит хук
ключей echelon (Текущая модель): такое решение уходит echelon письмом в тот же день.

**Обновлено 2026-11-13:** вопрос ушёл echelon в ответе на `echelon-email-links-real`
(`echelon-email-links-real-outcome`).

**Status:** resolved 2026-11-14 → DL #4. echelon ответил: Zulip ставит разрыв строки и не
склеивает, `zulip` остаётся вне списка.
