# Сон общего слоя правил: урок вкладывается в слой, а не дописывается

> Вырос из Sidetrack #2 кристалла `rules-retro`: урок о поведении ассистента оставался в памяти проекта, а слой
> правил рос дописками. Владелец через grill и brainstorm 2026-10-19 выбрал другой путь: каждый урок сводится со
> слоем целиком, как во сне, и слой может переписаться.

## Назначение

Общий слой `~/.claude/vdm/rules.md` доходит до каждой сессии машины, но растёт по одной дописке: правило, к нему
таблица, случаи, строка `Origin`. В сессию попадают только заголовок и первый абзац, и бюджет 9000 байт почти
исчерпан. А урок о поведении часто вообще не доходит до слоя и остаётся в памяти проекта (12 поправок в 4
проектах, ретроспектива 2026-10-18).

Цель — механизм, при котором урок в том же ходу вкладывается в слой: субагент читает слой целиком вместе с уроком
и возвращает слой, где урок уже растворён, при нужде переписав одно правило или несколько. Владелец (Q7):
«Зачем мне 10 фраз от меня про какую-то тему если это можно переписать одной более общей фразой для LLM. В целом
фразы сразу должны быть более общими изначально». Критерий успеха: первый глубокий проход сводит текущий слой и
38 записей `conduct`, слой влезает в бюджет с запасом, и владелец принимает разницу.

## Текущая модель

- **Слой** 2026-10-19: 16 правил, 8371 из 9000 байт (93%); файл 31 162 байта. Сессия видит заголовок и первый
  абзац; остальное — только если откроет файл. Из 5132 транскриптов машины `rules.md` читали 31 сессия, 24 из
  них — чтобы править; чтобы применить правило — 7 сессий в 3 проектах. Таблицы, случаи и `Origin` до работающих
  сессий почти не доходят.
- **Память проектов** 2026-10-19: записей `conduct` без `shared:` — 38 в 11 проектах, поднято 21; `hq` без
  `shared:` — 41 в 5 проектах, поднято 20. Подсказка `memory-scope` говорит, что урок «соберёт слой доступа», а
  договорённость в кристалле слоя доступа (07.10) — «в том же ходу бриф держателю общего слоя, локальная запись
  становится указателем». Наша сторона от договорённости отстала.
- **Хранилище**: `~/.claude` — ссылка в папку с именем Dropbox, но синхронизирует её Syncthing (владелец,
  2026-10-19). Своей истории версий у `rules.md` нет; две машины и параллельные сессии пишут в один файл.
- **Готовых средств нет** (2026-10-19): документация Claude Code о памяти не описывает сведения файлов; «Auto
  Dream» известен только по блогам и касается собственной auto memory; «Dreaming» Managed Agents — превью API над
  своим хранилищем. Скилл `writing-for-agents` (стороннего плагина, установлен на машине) — руководство по письму
  для модели: ведущие слова, цель вместо запрета, вычистка no-op и осадка.
- **Механизм** установлен 2026-10-19 (vdm 2.51.0): шаг сведения в `/vdm:learn` с промптом
  `skills/learn/fold-lesson.md`; запись — `scripts/rules-write.py`; подсказка `memory-scope` ведёт урок
  `conduct` в `learn` при записи.
- **На машине** 2026-10-20: vdm 2.52.0, vdm-comms 0.34.0 — сведение, скрипт записи, подсказка `memory-scope` и строка
  об указателях на исчезнувшие правила установлены.
- **Ответы** на 2026-10-20: слой доступа принял договорённость (сбор — подстраховка), перенёс адреса в своём кристалле на
  новые заголовки, сбор 49 записей `hq` — за ним, раскладка — решение владельца; ещё одного агента он отправил сводить его
  правило через `/vdm:learn`. Из четырёх проектов с письмами `rules-layer-folded-pointers` 20.10 ответил проект
  контента: все пять указателей поставлены. Три не ответили; их записи называет строка `memory-scope` при старте,
  пока строки не поставлены.
- **Слой после первого глубокого прохода** 2026-10-19: 15 правил, 7626 из 9000 байт (85%), файл 7760 байт; прежняя
  версия — в `~/.claude/vdm/history/`. Лёгкого сведения из другой сессии ещё не было.
- **Поле** 2026-10-20, 27 транскриптов машины после прохода: в `history/` по-прежнему одна версия. Уроков `conduct`
  после прохода записано два, у исполнителя и у агента машин, оба сессиями на vdm 2.50.1 и 2.46.2 со старой подсказкой
  «соберёт слой доступа». Ни одна сессия на 2.51+ урока `conduct` ещё не писала, так что основной путь — подсказка
  при записи — в поле не проверен. Живых сессий 12, из них 7 на vdm старше 2.51.0 (Sidetrack #4). Новая сессия агента
  машин на 2.52.0 получила при старте строку «сведи сейчас» и урок не свела (Sidetrack #3).
- **Лёгкие сведения в поле** 2026-10-20…22: пять, из четырёх других проектов (теги сессий в `history/` — глобальный штаб
  ×2, слой доступа, `vdx`, ещё один рабочий проект). Каждое прошло через `rules-write.py` с замером; слой вырос с 7626 до 8989
  байт, и следующее уже не влезало — три брифа «пора на глубокий проход».
- **Слой после второго глубокого прохода** 2026-10-22: 16 правил, 7730 из 9000 байт (86%), файл 7864 байт; прежняя версия
  — `history/rules-20261022T030614Z-40d45c93.md` (DL #10).

### #4. Сессии месяцами работают на старой версии плагина

**Возникло в:** «Текущая модель» → «Поле» 2026-10-20
**Описание:** версия плагина фиксируется при запуске процесса: `/clear` и сжатие перезапускают хуки той же версии.
Сессия агента машин прожила с 08.10 по 20.10 на vdm 2.46.2. Из 12 живых сессий 7 работают на vdm старше 2.51.0, две из
них с 08.10 на 2.44.0. До них не доходит ни новая подсказка, ни шаг сведения в `learn`, так что охват механизма
ограничен перезапусками. Кандидат: хук сравнивает свою версию с `installed_plugins.json` и одной строкой говорит, что
сессия отстала. Чей это акт, vdm или `vdx` (который запускает сессии), не решено.

Анализ 2026-10-20, без кода (владелец: «без изменений кода пока анализ»):
- Снимок ~20:10Z, только эта машина: живых процессов 13, из них 7 на vdm старше установленной 2.52.0, у одного
  версию не определить. Два живут 12 дней на vdm 2.44.0 и на Claude Code 2.1.294 при текущей 2.1.304. Отстаёт весь
  процесс: харнесс и все плагины.
- Сессия агента машин 08.10–16.10 — один процесс (Claude Code 2.1.291 всё время): 13 раз `SessionStart:compact`, и
  все из 2.44.0.
- По документации Claude Code (plugins/loading, cli-reference): версия держится до перезапуска или `/reload-plugins`.
  Он применяет хуки, скиллы, MCP и LSP без перезапуска. autoUpdate идёт раз за сессию, и строку «Run
  /reload-plugins» видит только обновившая сессия. Старый каталог хранится 14 дней. Переменной с версией для хука
  нет; сравнить можно `${CLAUDE_PLUGIN_ROOT}` с `installed_plugins.json`, но это вывод из раскладки, а не API.
- Довод за `vdx`: свойство процесса, а не плагина. Строка `vdx` «сессия несёт флаги профиля» уже сравнивает запуск с
  текущим. Почтовая сессия `vdx ai --intercom` — крайний случай. Письмо `stale-session-plugins` с вопросом, его ли
  это, ушло `vdx` 20.10.

Ответ `vdx` 21.10 (`stale-session-plugins-outcome`): сигнал его, в `vdx ai --check`, на SessionStart, только когда
сессия отстала. Отставший Claude Code — `vdx ai --restart <проект>`, отставшие плагины — `/reload-plugins`. Посылку «скажет
только загруженный код» он поправил: хук `vdx` зовёт глобальный CLI, а тот обновляется отдельно от сессии. Поэтому
сигнал дойдёт и до живущих сейчас сессий, пока цел каталог версии, из которого взят хук (14 дней). Как точно увидеть
`/reload-plugins`, ему ответили: запись `type: system`, `subtype: local_command` с `Reloaded: N plugins …` и временем
в транскрипте сессии.

**Status:** migrated → `vdx` (кристалл `vdx-ai`, Sidetrack #24), 21.10
