## Главный результат

**Completion-инвариант (`status: done` при непогашенных `- [ ]`) — ноль
нарушений во всех 12 репозиториях на 371 воркайтеме.**

Это ровно тот инвариант, ради которого существует третий слой:
`crystal-precommit-check.sh` — единственный downstream-бэкап, и он проверяет
именно его. То есть гейт, не установленный нигде, сегодня не поймал бы
ничего. Два слоя (PreToolUse-guard + Stop-reminder) фактически справляются.

## Канон: 37 нарушений, но почти все — законное наследие

Канон-чекер появился 2026-08-22 (vdm 2.16.0, коммит af4efcb). Разбивка по
дате последнего коммита файла:

- **34** — файлы, не тронутые с тех пор, как канон появился. Написаны под
  более ранним каноном. Это не нарушения дисциплины, а эволюция канона —
  ровно то, о чём CLAUDE.md говорит «canon is a floor, not a ceiling».
- **3** — тронуты позже. Из них:
  - `obsidianvault/inbox-triage` — **ложное срабатывание замера**: все 33
    записи DL датированы 2026-07-17…2026-08-22, то есть содержимое старше
    канона; файл лишь дописан позже. Дата последнего коммита — плохой прокси
    для долгоживущего кристалла.
  - `obsidianvault/hersheypark-2026-debrief` — **настоящее свежее нарушение**.
    Создан 2026-08-26, все 6 записей DL от той же даты, нет `## Sidetracks`,
    и в #1 стоит `Basis: precedent` — значение, которого в таксономии нет.
    Агент выдумал значение поля вместо того, чтобы взять из канона.
  - `t23b-content/trail-food-section` — отсутствует `## References`, больше
    ничего.

## Что из этого следует

1. **Ставить completion-гейт в 11 репозиториев незачем** — ловить нечего.
2. **Живая проблема — канон, а не completion.** И у канона downstream-гейта
   нет вовсе: `vdm-git` отгружает бэкап только для completion.
3. Оба свежих нарушения прошли мимо **активного** PostToolUse-хука. Значит
   вопрос не «поставить ещё один гейт», а «почему не сработал имеющийся» —
   правка не через ассистента, харнесс без PostToolUse, либо агент увидел
   exit 2 и не починил. До ответа на это любой новый слой строится вслепую.
