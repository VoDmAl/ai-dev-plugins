# fffd в vdm-git: проверка U+FFFD внутри git-guard-prepare и скриптом pre-commit

> Ломоть решения `comms-plugin` DL #11 (2026-09-21), отгружен 2026-09-22 как
> `vdm-git` v2.13.0. Открытым остаётся одно: три репозитория снимут свои копии
> после объявления — это работа в их деревьях.

## Назначение

**Цель.** Проверка «в содержимом коммита нет U+FFFD» живёт в `vdm-git` на двух
поверхностях: внутри `git-guard-prepare` (без установки, ловит каждый коммит,
подготовленный ассистентом, — то есть источник порчи) и отдельным скриптом
pre-commit (для коммитов из IDE и руками).

**Ограничение.** Никакого `|| true` вокруг `git diff --cached`: пустой список
из-за упавшей команды не должен читаться как «чисто».

**Критерий успеха.** Файл с U+FFFD в staged → обе поверхности отказывают с
перечнем файлов и строк; без порчи обе молчат; правка, не попавшая в индекс,
pre-commit-поверхность не успокаивает.

## Текущая модель

**Построено (2026-09-21):**

| Где | Что |
|---|---|
| `plugins/vdm-git/bin/git-guard-prepare` | блок проверки перед записью файлов сообщения: перечень путей уже валидирован выше, грепается каждый существующий файл |
| `plugins/vdm-git/scripts/fffd-precommit-check.sh` | читает **staged-блоб** (`git show :path`), не рабочее дерево |
| `tests/fffd.test.sh` | 16 проверок, обе поверхности, оба направления |

**Фикстура — байты, а не символы.** В тесте порча записывается как
`\xef\xbf\xbd`, потому что «символ замены», набранный в редакторе, редактор же
и нормализует; корпус воспроизводит форму исходного инцидента (кириллическая
буква, разрезанная пополам → два U+FFFD подряд).

**Найденный при этом дефект — в моей же первой версии скрипта.** Связка
`staged=$(git diff --cached -z --name-only)` даёт код возврата и **молча
выбрасывает нулевые байты**: имена файлов склеиваются в одну строку, не
совпадающую ни с чем, и проверка проходит на испорченном индексе. Случай с
одним застейдженным файлом при этом **проходил** — нулевой разделитель был
один, в конце. Поймал тест, который стейджит второй файл. Починено через
временный файл: и `-z`, и код возврата.

**Разделение ответственности между поверхностями названо явно:** у первой нет
шага установки и она покрывает источник порчи; у второй шаг установки есть, и
это её слабость — непроволоченный хук неотличим от чистого. Проверка
проволоченности — свойство машины и клона, то есть зона внешнего инструмента,
а не этого плагина.

### #2 / 2026-09-21 / Проверка внутри хелпера смотрит рабочее дерево, а не индекс

**Source:** assistant
**Basis:** observed
**Basis-detail:** блок вставлен **после** проверки «индекс против рабочего дерева»
(`git-guard-prepare`, секция `index vs worktree check`). К этому моменту хелпер
уже отказался бы, если содержимое расходится, — значит на путях из списка
рабочее дерево и индекс совпадают, и читать проще файл.
**Context:** вторая поверхность (pre-commit) читает именно staged-блоб, и
соблазн сделать одинаково был.
**Why:** одинаково здесь означало бы `git show :path` на путях, которые хелпер
через строку уже признал совпадающими, — лишний вызов git на каждый файл ради
свойства, которое уже гарантировано. Разные входы у двух копий вынуждены
(`suite.md` → «Дублирование лечится конформансом»), а не выбраны.
**Implication:** тест проверяет обе поверхности порознь, и для pre-commit — оба
направления staged/worktree отдельными случаями.

### #3 / 2026-09-21 / Подстановка команд несовместима с `-z`, и это стоило бы тихого пропуска

**Source:** assistant
**Basis:** observed
**Basis-detail:** первая версия `fffd-precommit-check.sh` делала
`staged=$(git diff --cached -z --name-only …)` и не находила порчу: bash
выбрасывает нулевые байты из подстановки команд, имена склеиваются
(`a.mdb.md`), `git show` по такому имени падает, цикл ничего не проверяет.
Случай с **одним** файлом проходил корректно — разделитель был единственным и
в конце, — поэтому первая проверка теста («чистый индекс → 0») зелёная, а
дефект живёт.
**Context:** нужны были одновременно два свойства: `-z` (имя файла может
содержать перевод строки) и код возврата `git diff` (пустой список из-за
упавшей команды не должен читаться как «чисто»). Конвейер даёт первое,
подстановка — второе.
**Why:** временный файл даёт оба. Цена — один `mktemp` и `trap`.
**Implication:** это второй случай за день, когда зелёный результат был
свойством фикстуры, а не кода (первый — симлинк в `gate-scope-symlink`).
Вывод для тестов суиты: фикстура с **одним** элементом не проверяет разделение
элементов, как фикстура с одним агентом не проверяет фильтр справочника.
