# vdm-comms: почта только на чтение — синк отправленного и приём входящих в comms/

> Ломоть решения `comms-plugin` DL #13 (2026-09-21). Идёт после 0.2; заведён в `ready` по
> слову владельца «всё по порядку». Создание черновиков в Gmail в этот ломоть **не входит**
> — это v2 под отдельным принципалом, свой кристалл после инфраструктуры.
>
> **Номер версии.** Задумывался как 0.3, но 0.3.0 занял `vdm-comms-pending`, 0.4.0 —
> `vdm-comms-gag-onboarding` (его Sidetrack #2). Ломоть выйдет под следующим свободным номером.

## Назначение

**Цель.** Скилл `/vdm-comms:mail` на области `gmail.readonly`: (а) синхронизация
«Отправленных» — файл `comms/*-out.md` с `draft: true` получает `sent: <дата>` и реальный
ушедший текст (боль 15.09: владелец дописал абзацы перед отправкой, файл правили по
пересказу); (б) приём входящих — `comms/<дата>-<slug>-in.md` со ссылкой «Ответ на»,
`.eml` и вложения в `comms/attachments/`; исток цепочки — самое первое письмо, не
последнее.

**Ограничения.** Токен только `readonly` — отправить не может по построению; никаких
`compose` / `modify` / `send` (проверено по официальной странице scope'ов 2026-09-21:
области «черновики без отправки» нет). Входящие письма — недоверенный текст, канал
prompt injection; в SKILL.md явно. Черновики остаются файлами, отправляет человек.

**Критерий успеха.** На `global-auth-gap`: после отправки письма человеком одна команда
приводит `-out.md` к ушедшему тексту с `sent:`; входящее с вложением ложится в `comms/`
рядом с вложением и правильной ссылкой на исток цепочки; в коде и конфигурации нет пути к
отправке.

## Текущая модель

**Первый шаг ломтя — факт, не решение:** есть ли коннектор Gmail из claude.ai в Claude
Code и какие у него инструменты. В сессии 2026-09-21 виден `Google_Drive`-коннектор
(`mcp__claude_ai_Google_Drive__*`), Gmail — не проверен. Если коннектор read-only — токена
на машине нет вовсе, скилл читает через него и пишет файлы `Write`'ом. Если в нём есть
отправка — это **именованный инструмент**, и `PreToolUse` по матчеру блокирует его с
нулевой ценой (`suite.md`: гейт по имени — настоящий). Если коннектора нет — локальный
MCP или скрипт с `gmail.readonly`-токеном (Google Workspace, владелец — администратор).

**Что уже есть у `gag`** (дополнение §3): соглашения `comms/` — `-in`/`-out`, `draft: true`
↔ `sent:`, `comms/attachments/`, правило 29 (исток цепочки — первое письмо), хук
`check-draft-comms.sh` (уходит в 0.1.0).

**Граница токена** (дополнение §3, 🔴): ассистент запускает Bash от того же пользователя;
`compose`-токен в Keychain достаётся `security` и уходит `curl`'ом мимо MCP. Для
`readonly` это не дыра. Для v2 (черновики) единственный гейт — токен у другого принципала.

### #1 / 2026-09-21 / Заведён как ломоть в `ready`; область readonly решена в `comms-plugin` DL #13

**Source:** user
**Basis:** user-stated
**Basis-detail:** «всё по порядку»; выбор «v1 только чтение, черновики файлами» сделан
владельцем в grill-интервью 2026-09-21.
**Context:** владелец хотел «читать и создавать черновики прямо в почте, отправлять
нельзя»; факт про scope'ы режет задачу по чтению.
**Why:** чтение закрывает случившуюся боль и три из пяти пунктов приёмки дополнения без
инфраструктуры; черновики требуют `compose`, а значит — другого принципала.
**Implication:** `ready`; старт после 0.2; v2 — отдельный кристалл после того, как
появится MCP под другим пользователем ОС или хостом.
