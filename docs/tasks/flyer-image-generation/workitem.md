# Флаеры и постеры через модели картинок

> Поручение владельца через агента `program`, 13.11: найти или сделать подход, которым агент
> любого проекта владельца доводит флаер или постер до уровня двух образцов, сделанных людьми,
> через модели картинок (DALL-E / gpt-image, Gemini nano banana). Заведён сессией intercom как
> парковка; работа — основной сессии.

## Назначение

Агент контента сверстал флаер благотворительного завтрака HTML-ом (фото + рисунок →
`render-flyer.py` → PNG и PDF), и владелец назвал результат «не очень» рядом с двумя флаерами
людей, которые выглядят хорошо. Владелец предложил делегировать работу модели картинок и
спросил, есть ли для этого скиллы — «полезно во всех моих проектах».

Нужен метод, а не один флаер: как делится работа между агентом (текст, композиция, промпт,
проверка) и моделью картинок, и где живёт текст флаера, чтобы дата, цена и адрес не «уехали»
вместе с картинкой. Критерий успеха — первый живой случай: флаер того же завтрака у агента
контента выходит на уровень образцов, и владелец это подтверждает. Срока нет: флаер нужен после
решения «быть» у `program`, оно ⏰ 2027-02-01.

Перед кодом — линза из `CLAUDE.md` («не всё, что мы придумали, должно ехать отсюда»): поведение
при акте «агент делает флаер» — сюда; «в каждом проекте должен лежать ключ API» — не сюда.

## Текущая модель

- **Хороший образец № 2 сделан моделью картинок целиком, текст тоже.** В файле флаера
  ярмарки венков лежит манифест C2PA: `softwareAgent` ChatGPT, `gpt-image`,
  `digitalSourceType: trainedAlgorithmicMedia`, подпись OpenAI, создан 2026-11-12. Размер
  1024×1536 — портретный размер gpt-image. Даты, цены, адрес, ссылка и почта отрисованы
  моделью и читаются чисто (DL #1).
- **Образец № 1 (завтрак другого отряда), скорее всего, тоже**: тот же стиль (фотореальная
  еда, плашки-«стикеры», рукописный заголовок), но это JPEG 1043×1181 без C2PA — пересжат по
  дороге. Не доказано (DL #1).
- **Значит, вопрос «скилл или нет» уже наполовину отвечен полем**: люди получают хороший
  результат одним промптом в ChatGPT. Слабое место такого пути — текст: модель может исказить
  цифру, и никто не сверяет. Метод для агента = промпт с точным текстом + сверка
  отрисованного текста с источником + правка, а не «нарисуй красиво» (гипотеза к проверке).
- **Готовые скиллы есть** под обе модели (поиск 13.11, сторонние каталоги, не проверены): под
  nano banana — несколько, большинство через MCP-сервер и `GEMINI_API_KEY`, один ходит в веб-чат
  Gemini через Playwright; под OpenAI — скиллы на `gpt-image-1`/`1.5`/`2` с питоновым
  скриптом и `OPENAI_API_KEY`. Сверки текста после генерации ни в одном описании не видно.
- **API нет, только чат** — слово владельца 14.11: «Только чат — ChatGPT и Gemini» (DL #2).
  Это совпадает с тем, что видно на машине: ключей `OPENAI_*`/`GEMINI_*`/`GOOGLE_*` нет ни в
  окружении сессии intercom, ни в `env` у `~/.claude/settings.json`, MCP-сервера картинок нет в
  `claude mcp list` (13.11). Картинку генерирует владелец в чате, агент её не вызывает.
- **Готовые скиллы под API отпадают**: почти все сторонние скиллы выше ходят в модель по ключу
  (`GEMINI_API_KEY`, `OPENAI_API_KEY`). Один ведёт веб-чат Gemini через Playwright, то есть
  действует в учётной записи владельца автоматом — решать в Sidetrack #2, не брать по умолчанию.
- Где жить скиллу — не решено: новый плагин, `vdm-comms` (исходящий текст с датой и ценой) или
  чужой готовый скилл, установленный пользователю (Sidetrack #2).

## Decision Log <!-- crystal-lint: optional -->

### #1 / 2026-11-13 / Образцы сделаны моделью картинок: метод строится вокруг сверки текста

**Source:** assistant
**Basis:** observed
**Basis-detail:** сессия intercom 13.11 открыла оба образца в checkout агента `program`
(`attachments/large/wreath-sale/…-v1.png`, `program/2026-2027/pancake-breakfast/…-flyer.jpeg`)
и прочла строки файлов: у PNG — манифест C2PA (`claim_generator_info` OpenAI Media Service API,
`softwareAgent` ChatGPT / `gpt-image`, `trainedAlgorithmicMedia`, 2026-11-12T14:49Z), размер
1024×1536 по `sips`; у JPEG маркеров C2PA, OpenAI, Gemini, SynthID нет, 1043×1181. Файлы не
скопированы в `references/`: на них реальные люди, организация, адрес и почта, а репозиторий
публичный (вето провенанса); воспроизводится `strings -n 4 <png> | grep -i -E 'softwareAgent|claim_generator|trainedAlgorithmic'`.
Что JPEG тоже из модели — вывод по стилю, не наблюдение.
**Context:** бриф говорил «оба сделаны людьми, не агентом» и «чем сделан второй, в наших
источниках не видно». От ответа зависит, что строить: инструмент вёрстки (HTML лучше) или
метод работы с моделью картинок.
**Why:** человек сделал хороший флаер одним заходом в ChatGPT, текст отрисован моделью. Значит,
красоту даёт модель, а агенту остаётся то, чего у человека в этом пути нет: точный текст в
промпте, проверка отрисованных цифр против источника, повтор до совпадения. HTML-вёрстку
улучшать отвергнуто как основной путь: проигрыш образцам — в изобразительной части (еда
крупным планом, насыщенный фон), а её HTML не даёт.
**Implication:** скилл описывает цикл «текст из файла → промпт → картинка → чтение картинки
агентом → сверка с файлом → правка/повтор», и текст флаера живёт в файле проекта, а не в
промпте. Запасной вариант на случай, когда модель упорно портит цифры, — фон и иллюстрация от
модели, текст поверх кодом (как делает соседний проект карточек 1200×630 на `@vercel/og`).
**Cross:** см. Sidetrack #1, #2

### #2 / 2026-11-14 / Генерирует владелец в чате; агент готовит промпт и текст и сверяет результат

**Source:** user
**Basis:** user-stated
**Basis-detail:** ответ владельца на вопрос сессии intercom 13.11 (`intercom ask` через сессию
агента `program`, где владелец дал поручение): «Только чат — ChatGPT и Gemini», из четырёх
вариантов (API OpenAI / API Gemini / оба / только чат). Письмо `flyer-image-generation-ask-answer`
от 14.11 (store intercom, ящик `ai-dev-plugins`, после разбора в `_done/`); `check` нашёл эти слова
в транскрипте той сессии после вопроса (`🗣 … found`).
**Context:** Sidetrack #1. С API агент генерировал бы сам, без API — готовит, а генерирует владелец.
**Why:** ключа нет ни у одной модели, а заводить его владелец не предлагал. Путь «промпт в чат»
уже дал образец № 2 (DL #1), так что меняется только то, кто нажимает «сгенерировать».
**Implication:** цикл скилла: агент пишет текст флаера в файл проекта и промпт с этим текстом
дословно → владелец запускает промпт в ChatGPT или Gemini и кладёт картинку в проект → агент читает
картинку и сверяет каждую дату, цену, адрес, ссылку с файлом → при расхождении — промпт правки,
повтор. Ход владельца в каждом заходе один: запустить и положить файл. Сторонние скиллы на API
отпадают, наш слой «текст и сверка» нужен в любом случае (Sidetrack #2).
**Cross:** см. Sidetrack #1, #2

## Sidetracks

### #1. Доступ владельца к моделям: чат или API

**Возникло в:** Текущая модель → ключи API
**Описание:** От ответа зависит форма скилла. С API агент генерирует сам (ключ нужен в
окружении; кто его держит и где — вопрос к владельцу, может быть, через слой доступа). Без API —
агент готовит промпт и текст-эталон, владелец генерирует в чате, агент читает результат и
сверяет. Второй путь уже идёт у агента контента («промпт пишет контент, генерирует владелец»,
со слов брифа), но без метода и без проверки.

**Status:** resolved 2026-11-14 → DL #2. Только чат: генерирует владелец, агент готовит и сверяет.

### #2. Где живёт скилл

**Возникло в:** Назначение
**Описание:** Варианты: (а) готовый сторонний скилл под nano banana или gpt-image, поставленный
владельцу, плюс наш короткий слой «текст и сверка»; (б) свой скилл в `vdm-comms` — флаер это
исходящий текст с датой и ценой, сверка с источником там уже в духе `letters`; (в) отдельный
плагин. Решать после #1 и пробного прогона.

**Status:** open
