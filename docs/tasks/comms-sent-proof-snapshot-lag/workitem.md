# comms: `sent-proof:` письма, ушедшего после последнего сбора почты, получает отказ как выдуманный

> Заведён сессией intercom 2026-11-17 по письму агента одного из рабочих проектов владельца. Делает основная сессия
> владельца: сессия intercom код не правит, рабочее дерево общее. Письмо пересказано, имён людей, проектов, путей и
> Message-ID здесь нет (CLAUDE.md, правило 7); адрес письма — в DL #1.

## Назначение

**Входящее.** 16.11, дважды за вечер. Черновик положен через echelon (`mail_draft` из файла), владелец отправил его
из почтового клиента. echelon прислал проекту событие «Письмо ушло»: письмо intercom со slug `draft-sent-<дата>-<n>`,
в нём uid черновика, файл и Message-ID. Живой `mail_search in:sent` показывает письмо. Агент ставит в файл `sent:` и
`sent-proof: <этот Message-ID>`, и хук отказывает: в журнале echelon отправки нет, а в снимке почты, собранном за
две минуты до отправки, письма с этим Message-ID нет. Во втором случае письмо ушло через 11 минут после сбора. Агент
обошёл отказ через `sent-proof: owner`, хотя владелец про это письмо отдельно ничего не говорил.

**Просьба.** Принимать доказательством (а) событие echelon «Письмо ушло» по этому файлу или (б) живой поиск
Message-ID через echelon, когда снимок старше письма. Если ни то ни другое невозможно — в тексте отказа сказать
«снимок старше письма: подожди сбор или `/echelon:pull mail`», а не «доказательства нет».

**Готово, когда** настоящий Message-ID письма, отправленного после сбора, проходит гейт без слова владельца
(или получает отказ, который называет сбор, а не `owner`), выдуманный id по-прежнему получает отказ, выпуск
vdm-comms вышел (и, если нужно, правка echelon), отправителю ушёл итог.

## Текущая модель

- Гейт: `proof_verdict` → `journal_says` в `plugins/vdm-comms/scripts/comms_sent_proof.py` спрашивает
  `<access layer> sent <каталог письма> <id>`. Код 1 → отказ `NOT_CONFIRMED` с первой строкой ответа echelon, код 2 →
  «не могу сказать», без отказа. Прочитано в рабочем дереве 2026-11-17 (vdm-comms 0.43.0).
- Отставание снимка известно с 2026-11-03 ([[comms-sent-proof-hand-sent/workitem|comms-sent-proof-hand-sent]],
  «Текущая модель»): что ушло после сбора, получает 1 так же, как выдуманное. Тогда оно закрылось только тем, что
  строка ABSENT у echelon (коммит `0538d95`) называет момент снимка. Выхода, кроме `owner`, отказ не называет, и
  второй случай из письма показывает, к чему это ведёт: `owner` без слова владельца.
- Что echelon помнит о событиях «Письмо ушло» и может ли `sent` их читать — **не проверено**: известно только из
  письма отправителя.

[[comms-sent-proof-hand-sent/workitem|comms-sent-proof-hand-sent]] и кода гейта. **Не проверено:** в checkout'е
echelon не прочитаны `runtime/echelon/sent.py` и место, где echelon хранит события «Письмо ушло»; не проверено, что
форма строки ABSENT позволяет плагину сравнить момент снимка с `sent:` письма.
**Context:** три пути из письма: событие echelon, живой поиск, текст отказа.
**Why:** почта и события о ней есть только у echelon, гейт MCP вызвать не может. Если echelon сам примет свою запись
«Письмо ушло» (или спросит почту вживую), вызов и поле останутся прежними, и хуки старых версий получат исправление
без обновления — довод DL #1 соседнего кристалла. У плагина остаётся текст отказа: когда снимок старше `sent:`
письма, назвать сбор (`/echelon:pull mail`) и повтор. Отказ не превращается в «не могу сказать»: иначе любой
выдуманный id с поздним `sent:` проходит.
**Implication:** первый шаг основной сессии — прочитать код echelon, потом бриф ему. Отправителю ответ сейчас:
принято, раздел работы такой, мяч у нас.
