# vdm-comms на первом переключении: ссылки указателей, пропавшие черновики, владельцы, правила линтера, wikilink

> Вырос из интерком-брифа `vdm-comms-gag-onboarding-findings` (`global-auth-gap`,
> 2026-09-23): первый репозиторий, который попробовал **заменить** свои локальные
> `lint-meetings.py` и `pending.py` плагином, прошёл наш порядок (конфиг → `--check` → сверка
> со старыми скриптами на копии) и остановился. Решение их владельца — дорабатываем плагин,
> локальных надстроек не держим. Бриф пересказан, а не скопирован: см. DL #1.

## Назначение

**Цель.** Закрыть всё, что мешает `global-auth-gap` снять `lint-meetings.py`,
`pending.py` и оба `check-*.sh`: четыре дефекта (ссылка указателя короче на уровень;
`SENT_RE` перешагивает перевод строки; человек-дополнение становится владельцем; «мы» с
уточнением не распознаётся), три пропавших сигнала сводки (черновики Jira-тикетов, ⏰ в
очередях серий, встреча без транскрипта), порядок групп в `--owner`, девять правил линтера
встреч, режим wikilink и колонки реестра. Плюс P.S. к `vdm-git`: гейт U+FFFD читает бинарные
файлы.

**Ограничения.** Пол остаётся полом: всё, что не общее для трёх репозиториев, включается
ключом конфига и по умолчанию выключено (`comms-plugin` DL #6 — пожелания агентов
реализуются здесь, без точек расширения). Только стандартная библиотека python3. Формат
чужих файлов не мигрируется. rc-семантика гейтов прежняя.

**Критерий успеха — их приёмка §4, прогнанная у нас на копии их дерева до отправки ответа:**
1. указатель из `gaps/<x>/comms/` открывает встречу; `--check` показывает только ожидаемое
   переформатирование таблиц;
2. намеренно сломанная повестка даёт ошибки по каждому включённому ключу;
3. сводка показывает черновики `*-task.md` / `*-draft.md`, ⏰ из очередей серий и встречи без
   транскрипта; пункты 1.3 и 1.4 разрешаются как у старого инструмента.

### #9 / 2026-09-23 / Генератор: ссылка считается от каталога файла; wikilink — режим, markdown по умолчанию не тронут

**Source:** assistant
**Basis:** observed
**Basis-detail:** на копии их дерева после правки каждая ссылка всех 87 указателей
открывается: 211 в markdown, 258 в wikilink (плюс якоря тем), битых 0. Красный тест:
указатели треков глубины 1, 2 и 3 — старый генератор проходит только глубину 1.
**Context:** бриф 1.1 (относительный путь) и 2.4 (`link-style`, колонки, материалы и якоря).
**Why:** относительный путь делается в одном месте (`Writer`) из абсолютного, а не
склеивается префиксом: префикс знает про глубину трека столько же, сколько знал `../../`.
В режиме markdown треки остаются code span'ами, а таблицы по умолчанию — прежними колонками:
иначе каждый репозиторий, уже сделавший `--write`, получил бы дрейф ради Obsidian-режима, о
котором не просил. Колонки — два ключа (`registry-columns`, `series-columns`), потому что у
файла серии своя таблица и свой умолчательный набор. Якорь темы **читается** из тела
(`## Тема N. …`/`## Topic N. …`), а не составляется, и ставится только в wikilink: у
markdown-якорей своя схема слагов у каждого рендера. Текст якоря — заголовок как есть, с
двоеточиями, как писал их старый генератор; в самом Obsidian не проверялось. `pointer-line`
получил `%(ref)s`; старая форма `[%(source)s](%(link)s)` в переопределении продолжает работать.
**Implication:** в режиме markdown поменялась одна вещь — строка «материалы» в указателе
(просили для указателя, в обоих режимах она полезна); это разовый дрейф у всех, кто уже
писал указатели.

решение, что печатает `git diff` («Binary files differ»), и у проекта уже есть способ его
переопределить — `binary` в `.gitattributes`. Если поиск бинарных сломается, список пуст и
читаются все файлы: сломанный поиск стоит ложной тревоги, а не пропуска.
**Implication:** оба пропуска, найденные тут же (Sidetrack #4, #5), закрыты в этом же выпуске —
