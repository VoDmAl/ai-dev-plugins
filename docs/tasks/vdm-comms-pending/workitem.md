# vdm-comms 0.2: висяки — линт строки с владельцем, сводка по владельцу и сроку, оба маркера срока

> Ломоть решения `comms-plugin` DL #12 (2026-09-21). Идёт после 0.1.0
> (`vdm-comms-core`); заведён в `ready` по слову владельца «всё по порядку». Закрывает
> вопрос `limeflow` из `wait-due-outside-crystals` (ответ отправлен 2026-09-21).
> **Отгружен 2026-09-22 как `vdm-comms` 0.3.0** — см. DL #2.

## Назначение

**Цель.** В `vdm-comms` 0.2 — порт `pending.py` из `global-auth-gap`: (а) PostToolUse-линт
**новых** строк висяков в файлах из конфига — владелец обязателен, контрагентские первыми;
(б) `/vdm-comms:pending` — сводка «кто кому что должен и к какому сроку», группировка по
владельцу; (в) SessionStart — просроченные и «7 дней». Детектор читает оба маркера срока:
`⏰ <дата>` / `⏰ после: <событие>` и `(due: YYYY-MM-DD)`.

**Ограничения.** Кристаллы `vdm` (`crystal-hydrate`, `(due:)` в `workitem.md`) не меняются;
интерком не учится «ждать ответа со сроком». Форматы не мигрируются. Та же rc-семантика
гейта, что в 0.1.0 (`comms-plugin` DL #10).

**Критерий успеха.** У `global-auth-gap` сводка плагина совпадает со сводкой их
`pending.py` на тех же файлах; у `space-hq` строки с `⏰` читаются без правок; у `limeflow`
ожидания `(due:)` в `docs/tasks/<ключ>/<slug>.md` попадают в просрочку на SessionStart
после добавления путей в конфиг; их собственный grep снят.

## Текущая модель

Отгружено в `vdm-comms` 0.3.0: `scripts/comms-pending.py` (сводка · `--owner` · `--all` ·
`--json` · `--lint [--changed] [--cap N]` · `--brief` · `--print-contract`),
`scripts/comms-pending.sh` (PostToolUse-хук + CLI, fail-closed),
`scripts/comms-pending-check.sh` (SessionStart, fail-open), `skills/pending/SKILL.md`,
пять ключей конфига в `comms_config.py`, `tests/comms-pending.test.sh` (61).

**Приёмка на живых данных.** Сверено с `pending.py` на копии 45 файлов `global-auth-gap`:
множество пунктов совпадает (304 против 303 — лишний у нас настоящий), расхождений по дате
два, оба в нашу пользу. Расхождения по владельцу разобраны поклассово (DL #3); ни одно не
случайно. На копии `space-hq` детектор читает все четыре их формы строки без правок в их
файлах.

**Чего в ломте нет и почему.** Встречи без транскрипта и хуки очередей серий из `pending.py`
не переносились: это сигналы слоя встреч, у которого в этом плагине уже есть свой
генератор и свой дрейф. `--strict` не переносился: у хука своя rc-семантика.

### #3 / 2026-09-22 / Правило владельца построено по корпусу, а не по документации источника

**Source:** assistant
**Basis:** measured
**Basis-detail:** замер на 314 живых пунктах `global-auth-gap`. Документированная форма
`**<владелец>** — <что>` покрывает 111 из 314; остальные 203 пишут владельца иначе.
Поиск известного имени по всей строке дал 61 приписку не тому владельцу
(`Завершить миграцию ETNA → Kratos` → команде Kratos; `Реактивировать диалог с СБ` →
безопасности): имя было предметом, а не тем, у кого мяч. У `space-hq` контрагент стоит
**после** первого тире (`⏰ 2026-09-15 — Finance — …`) либо в бэктиках, а жирным выделена
**дата**.
**Context:** прямой порт `parse_owner` воспроизвёл бы и форму, и её собственные промахи —
их `PEOPLE_LINK_RE` не читает экранированную вертикальную черту, и 27 пунктов с людьми
уходили в «нет владельца».
**Why:** документация формата — заявка, корпус — факт; при расхождении переносить надо
корпус, иначе переносится представление инструмента о себе.
**Implication:** поиск ограничен **головой пункта** — до первого разделителя, после шага
через ведущий маркер даты; жирная дата владельцем не считается; незамаркированное имя
принимается, только если голова с него **начинается**. Люди группируются по слагу профиля
(«Харламов»/«Харламова»/«Харламову» — один владелец). Белый список `comms.owners` остаётся:
структурного признака, отличающего владельца от предмета, нет.

### #6 / 2026-09-22 / Сломанный срок — нарушение, `dd.mm` вне ISO — замечание, голый `⏰` — «нет даты»

**Source:** assistant
**Basis:** measured
**Basis-detail:** первая версия считала сломанным любой `⏰` без разбираемой даты — 26
нарушений на `gag`, включая `до 8.19.1` (номер версии) и строки, где `⏰` служит **меткой
пункта**, а дата стоит отдельно или отсутствует.
**Context:** правило кристаллов — «сломанный срок нарушение, отсутствующий нет»
(`crystal-grow` § «Обещание со сроком»).
**Why:** `dd.mm` — неоднозначная форма (версия, номер раздела), и неразобранная не значит
сломанная; сломанным может быть только то, что заявлено датой явно.
**Implication:** «сломан» = `(due: <не-ISO>)` или `⏰ <ISO-образная, но невозможная>`. Всё
остальное — «нет даты», и это нарушение только внутри объявленной секции.

### #7 / 2026-09-22 / Вычистка git-сессии — в каждый тест, а не в те, что запускает гейт

**Source:** assistant
**Basis:** measured
**Basis-detail:** первый коммит этого ломтя упал с `invalid object … for
'.claude/vdm-plugins.json'`. Воспроизведено отдельно: `GIT_INDEX_FILE` указывает на временный
индекс коммита, и фикстурный `git add -A` заменил **158 записей на 9**.
**Context:** вычистка существует с 2026-09-04, но стояла в двух наборах — тех, что гейт
запускал тогда. Расширение гейта 7 до четырёх наборов сделало два новых достижимыми из хука.
**Why:** инвариант, записанный там, где он сейчас нужен, а не там, где он верен, ломается при
первом изменении вызова; предикат «использует ли тест git» пришлось бы применять руками к
каждому новому файлу.
**Implication:** вычистка в каждом `tests/*.test.sh` (13 файлов дописано), утверждение
пофайлово в `tests/gates-harness-isolation.test.sh`, триггер пробы — любой застейдженный
`tests/*.test.sh`. Записано в `docs/model/suite.md` → «И четвёртое, 2026-09-22».
