# vdm-comms: скилл писем — что писать в исходящем, и чеклист в момент черновика

> Четыре письма соседей от 2026-09-25…28 просят одно: правила о **содержании** исходящего письма
> общими для всех проектов с vdm-comms, а не переписанными в каждом CLAUDE.md. Главное —
> `common-layer-from-claude-md` от program: владелец решил вынести общий слой из CLAUDE.md трёх
> проектов, для писем — новым скиллом в vdm-comms с хуком.

## Назначение

**Цель.** Скилл писем в vdm-comms (рабочее имя `/vdm-comms:letters`) и хук: при создании
`*/comms/*-out.md` в контекст ассистента приходит короткий чеклист. Регистр и язык исходящих — параметры
проекта (`comms.register`, `comms.language`), профили регистра описаны в скилле. В тот же скилл
ложатся правила из трёх соседних писем: канал берётся из слова владельца, а перед вопросами идёт
раздел «Знаем сами» (hq); в треде отвечают на последнее сообщение собеседника (product);
черновик начинается с заготовки под канал (program, п. 2).

**Ограничения.** Механику файла письма (черновик, `sent:`, форма по каналу, 📎, `.eml`) скилл не
повторяет, он ссылается на `/vdm-comms:meetings`. Истории «Пойман…» в скилл не идут: у правила одна
строка «почему», журнал случаев живёт в проекте. Текст агент-агностичный (CLAUDE.md этого репо).

**Критерий успеха** (приёмка из брифа program):
- в проекте с vdm-comms черновик `*/comms/*-out.md` при создании приносит в контекст чеклист;
- скилл писем содержит разделы оглавления синтеза;
- `comms.register` и `comms.language` читаются, профили описаны;
- правила hq, product и заготовка executor — на своих местах, каждое с проверкой там, где она
  механически возможна.

## Текущая модель

Состояние на 2026-09-28, до начала работы:

- **`goal` в `letter-form`** — с vdm-comms 0.8.0: цель есть и не пуста, форма YAML любая.
- **`known` в `letter-form`** — с vdm-comms 0.9.0: вопрос в тексте без строки «Знаем сами» / «What we know» — предупреждение. До ассистента в момент записи оно пока не доходит (Sidetrack #5).
- **Что плагин уже знает о письмах — только механику.** Раздел «Outgoing letters» скилла
  `meetings`: гард создания (`sent: <дата>` в новом письме — отказ), форма по каналу
  (`comms.letter-form`), черновик вне `comms/`, гард сырого `.eml`, чеклист 📎, абзац о волонтёре.
  Черновиком с 0.6.6 считается `draft: true` или `sent: false` (crystal-wake, Sidetrack #22). О
  содержании письма — цель, адресат, регистр, обещания, вычитка — в плагине ничего нет. Хука,
  который приносит что-то в контекст при создании черновика, нет; есть только линтер формы после
  записи.
- **Содержание уже собрано, и не нами.** program разложил 641 правило трёх CLAUDE.md на 312
  кластеров: `~/AI Projects/program/docs/tasks/claude-md-slimming/references/synthesis.md`. В
  нём готовы оглавление скилла (13 разделов, по каждому номера кластеров К#) и текст чеклиста для
  хука (15 строк). Кластеры `letters` — разделы синтеза «Письмо: …», «Входящее», «Соседние агенты».
- **Решения владельца приняты как вход** (DL #2): скилл + хук, одиночные общие правила тоже
  выносятся, регистр и язык — ключи в `vdm-plugins.json`.
- **Владелец ответил 2026-09-28:** `sent:` — письмо ушло из рук владельца, ставится правкой после
  его подтверждения, гард не меняется (DL #3); цель письма — `goal:` во frontmatter,
  элемент `letter-form` (DL #4; «одной строкой» снято в DL #6 — посылка не подтвердилась); проза, заметки и анализ — по-русски во всех проектах, это
  `rules.md`, а не скилл (DL #5).
- **Открыто для владельца:** формулировки трёх профилей регистра (п. 11–13) — показать готовым
  текстом скилла.
