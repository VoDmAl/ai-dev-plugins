# git-guard: проиндексированная соседом правка пути строки уходит в коммит молча

> Бриф агента личного хранилища заметок, 2026-11-04: строка коммита с путями ждала запуска, параллельная
> сессия того же репозитория дописала свою запись в общий `PROJECT_CHANGELOG.md` и проиндексировала его,
> строка прошла все проверки и забрала чужую запись. Ни при запуске, ни после ничто об этом не сказало.
> Заведён сессией intercom 04.11; код не тронут — работа для основной сессии.

## Назначение

Строка коммита с путями (`git commit -F … -- <paths>`) должна отказывать, когда содержимое её путей в
индексе изменилось после подготовки не её сессией, — так же, как она уже отказывает на непроиндексированную
правку и как строка без путей отказывает на любое изменение индекса. Общие файлы (`PROJECT_CHANGELOG.md`,
`.claude/memory/MEMORY.md`, workitem'ы) правят несколько сессий сразу, поэтому случай не редкий.

Условие: не сломать то, что хелпер сам велит ассистенту, — «правки путей ждущей строки едут с ней, когда
проиндексированы» (`git-guard-prepare`, раздел «Superseding kills the earlier line»; `guard/SKILL.md`,
«Hand off nothing new»). Критерий успеха: проверка двумя сессиями — подготовка в первой, правка и `git add`
того же файла во второй, запуск строки — отказ с именем пути; своя правка первой сессии после подготовки
по-прежнему едет без новой строки.

## Текущая модель

- **Случай подтверждён по коммиту отправителя** (DL #1): в коммите 66 вставок, в hunk'е changelog'а — запись
  параллельной сессии; её собственный коммит через 14 секунд changelog уже не содержит.
- **Почему молчит рантайм-проверка.** Строка с путями сверяет рабочее дерево с индексом
  (`git diff --stat --exit-code -- <paths>`). Сосед, сделавший `git add`, оставил их равными.
- **Почему молчит детектор.** `.blobs` подготовки сверяется с коммитом (`CHANGED SINCE PREP`) **только если
  HEAD сдвинулся** между подготовкой и запуском — так отсечены форматирующие pre-commit-хуки. В случае
  отправителя HEAD не двигался, поэтому молчали и `--verify-last`, и следующая подготовка. SWEPT IN /
  NOT COMMITTED сравнивают имена путей и такой случай не видят по построению.
- **Шапка хелпера утверждает неверное**: «the detector reports that one on the next prep»
  (`plugins/vdm-git/bin/git-guard-prepare`, раздел «A path changed after it was staged»). При неподвижном
  HEAD — не сообщает (Sidetrack #1).
- **Предложение брифа как есть ломает разрешённый поток** (DL #2): сверка blob'ов индекса с записанными при
  подготовке откажет и на собственный `git add` ассистента после подготовки, а хелпер именно его и
  предписывает вместо `--supersede`.
- **Готовый образец уже есть в той же строке**: форма без путей пишет `git write-tree` при подготовке и при
  запуске делает `git diff --cached --stat --exit-code <tree>`. Для форм с путями — то же с
  `-- <paths>`. Открыт вопрос, как своя проиндексированная правка обновит записанное дерево, если оно вшито
  в текст строки (Next actions).

## Decision Log

### #1 / 2026-11-04 / Случай отправителя подтверждён по его коммиту, механизм — по коду хелпера

**Source:** assistant
**Basis:** observed
**Basis-detail:** бриф — `<store>/ai-dev-plugins/_done/git-guard-shared-file-sweep.md` (store intercom, вне
репозитория). Коммит прочитан в checkout'е отправителя на этой машине, только чтение
(`GIT_OPTIONAL_LOCKS=0 git show --stat`, `git show -- PROJECT_CHANGELOG.md`), 2026-11-04 22:35 EST: 8 файлов,
66+/15-, в changelog'е новая чужая секция сверху; следующий коммит соседа (через 14 с) changelog не трогает.
Адрес и хэш коммита в репозиторий не перенесены: это чужой приватный репозиторий. Механизм —
`plugins/vdm-git/bin/git-guard-prepare` в рабочем дереве 2.26.1: детектор, условие
`"$(git rev-parse --verify -q "$parent")" != "$recorded"` перед сверкой `.blobs`; строка с путями —
`drift_diff` (`git diff --stat --exit-code --`); форма без путей — `write-tree` и
`diff --cached --stat --exit-code $index_tree`. Хелпер установленной на этой машине 2.26.0 побайтно равен
файлу в репозитории (`cmp`, 2026-11-04). Какой версией готовилась строка у отправителя, не проверялось; машина
та же, на которой стоит 2.26.0.
**Context:** бриф говорит, что SWEPT IN / NOT COMMITTED не напечатаны, и предлагает сверку индекса в строке.
Нужно было понять, баг ли это реализации или пробел дизайна.
**Why:** обе проверки работают как написано: рантайм-сверка смотрит дерево против индекса, детектор — только
при сдвинутом HEAD. Это пробел дизайна, признанный в шапке, но шапка ошибочно обещает, что детектор его
покроет.
**Implication:** правка — новая проверка в строке, а не починка старой; плюс исправление шапки.

### #2 / 2026-11-04 / Сверка индекса из брифа — не как есть: нужен путь для своей проиндексированной правки

**Source:** assistant
**Basis:** inferred
**Basis-detail:** из текста хелпера (сообщение об ждущей строке, ~стр. 1062: «Edits to the paths it names
ride with it once staged») и `guard/SKILL.md` («Hand off nothing new»). Не проверено: как часто ассистент в
поле действительно доиндексирует пути ждущей строки — по транскриптам не считалось.
**Context:** бриф: записать blob'ы при подготовке, сверить в строке, отказать при расхождении. Индекс не
знает автора правки — это сказано и в шапке хелпера.
**Why:** голая сверка превращает каждую свою доправку в `--supersede`, которое хелпер разрешает только при
провале строки или смене сути блока, — правило ждущей строки пришлось бы переписать. Отвергнуто и
противоположное: оставить как есть и только исправить шапку — пробел остаётся, а чужая запись в
опубликованном коммите не отменяется.
**Implication:** выбор формы — в Next actions: (A) сверка с деревом подготовки по путям строки плюс команда
хелпера, которой ассистент после своего `git add` перезаписывает дерево ждущей строки (scope — сессия,
поэтому чужая сессия так не «освятит» свою правку); (B) только детектор без условия на HEAD, сверяя `.blobs`
со снимком индекса, сделанным строкой перед `git commit`, — сообщает после коммита, не предотвращает;
(C) только исправить шапку. Рекомендация сессии intercom — (A).
