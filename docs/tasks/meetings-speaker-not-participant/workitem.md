# Линтер встреч: источник высказывания в протоколе не из `people:` встречи

> Бриф одного из штабов (hq) от 06.11 (`meeting-lint-speaker-not-participant`). Сессия intercom приняла его в
> кристалл и код не трогала: правка — для основной сессии владельца, рабочее дерево у них общее. Бриф пересказан,
> адрес оригинала — в DL #1. Срока штаб не назвал.

## Назначение

**Случай (штаб, 05–06.11).** В протоколе встречи (`meetings/<дата>-<slug>/index.md`) стояла строка вида
«Сидорова — Петров сказал, что …». Петрова на встрече не было, в `people:` встречи его нет. В транскрипте на этом
месте — название места, которое распознавание речи превратило в слово, похожее на фамилию, а сессия, писавшая
протокол, сделала из него человека. Следующая сессия взяла строку протокола как факт и построила на ней вывод для
владельца. Владелец назвал это критической ошибкой.

**Просьба.** В линтер встреч (`plugins/vdm-comms/scripts/comms-lint.py`) — проверку `meetings/*/index.md`: строка,
где человек назван источником высказывания («X сказал / говорит / сообщил», «по словам X»), X не в `people:` встречи
и рядом нет таймкода транскрипта (`00:41:36`), получает **предупреждение**: «X не участник встречи: пересказ или
ошибка распознавания — сверить с транскриптом и дать таймкод». X сопоставляется с карточками `people/` по фамилии в
любом падеже. Блокировать запись штаб не просит: предупреждение после записи, как у остальных проверок контракта.

Готово, когда:
- на `index.md` со строкой «Петров сказал …», где Петрова нет в `people:` и нет таймкода, линтер выдаёт
  предупреждение с фамилией и подсказкой про таймкод;
- та же строка с таймкодом рядом, или с участником встречи в любом падеже («по словам Сидоровой» при
  `people: [anna-sidorova]`), молчит;
- шум измерен на настоящем дереве встреч и записан в DL, до выбора формы правила;
- штаб получил итог.

## Текущая модель

- **Как в поле хранятся люди** (дерево встреч штаба, 06.11, DL #1): `people:` встречи — латинские слаги
  (`anna-sidorova`), файл карточки — `<people-dir>/<слаг>.md`. Имени в кириллице во frontmatter карточки нет
  (ключи: `trust` у всех 125, `identity` с `email`/`telegram_id` у 73, `addressed_as` у 3); оно стоит в заголовке
  `# …` — у 122 из 125 кириллицей. Значит, сопоставление «X из текста → участник» идёт так: слаг из `people:` →
  карточка → фамилия из заголовка → сравнение с X с учётом падежа. Слаг сам по себе фамилию в тексте не находит.
- **Что уже есть в линтере.** Свои правила проекта — `comms.meeting-rules`, каждое выключено, пока проект его не
  назвал (`_lint_meeting_rules`); `people-profiles` проверяет, что у каждого из `people:` есть карточка.
  Поиск карточки (`comms_people.find`) ищет целый токен, без падежей. Падежей в линтере сейчас нет нигде.
- **Масштаб в поле** (то же дерево, 06.11): 85 `index.md`, 78 из них с транскриптом рядом (`transcript.txt`).
  Строк с «сказал / сказала / говорит / сообщил / сообщила / по словам» — 111, из них с таймкодом
  `ЧЧ:ММ:СС` в той же строке — 34. Сколько из 77 остальных называют человека не из `people:` — не измерено
  (первый пункт Next actions): от этого числа зависит, предупреждение это или шум.
- **Форма правила не выбрана.** Язык глаголов и падежи русские, а пол контракта держит только то, что общее для всех
  полевых репозиториев. Скорее всего это правило `meeting-rules`, включаемое по имени, со списком глаголов от
  проекта, — но это не решено (Next actions).

## Decision Log

### #1 / 2026-11-06 / Фамилия участника — только в заголовке карточки, не в слаге и не во frontmatter

**Source:** assistant
**Basis:** observed
**Basis-detail:** бриф — `~/.claude/vdm/intercom/ai-dev-plugins/_done/meeting-lint-speaker-not-participant.md`
(хранилище intercom, вне репозитория; пересказан: в нём настоящие имена, а репозиторий публичный). Дерево встреч
штаба — его checkout из реестра intercom (`_registry/<идентичность штаба>.json` → `paths`), прочитано 06.11:
frontmatter встречи из брифа, ключи frontmatter всех 125 карточек `people/`, первые заголовки карточек, число
`index.md`, транскриптов и строк с глаголами речи (команды — `grep`/`awk` по `meetings/*/index.md` и `people/*.md`).
Имена и строки протоколов сюда не переписаны, только счёт. Сама строка из случая в протоколе уже могла быть
исправлена штабом — не проверялось.
**Context:** бриф просит сопоставлять X с карточками «по фамилии в любом падеже». Неясно было, где у карточки фамилия.
**Why:** слаги латинские, а X в протоколе — кириллица в падеже; во frontmatter имени нет; в заголовке оно есть почти
у всех. Другого источника фамилии на диске нет.
**Implication:** правило читает заголовок карточки каждого участника. Карточка без кириллического заголовка (3 из 125)
даёт участника, которого по фамилии не узнать, — решить, молчать ли тогда о любом X или предупреждать.

## Sidetracks

### #1. Таймкод можно сверить с транскриптом рядом

**Возникло в:** Текущая модель, «Масштаб в поле»
**Описание:** у 78 из 85 встреч транскрипт лежит рядом с `index.md`. Линтер мог бы проверять не только, что таймкод
есть, но и что в транскрипте на этом месте вообще есть такая отметка. Это сравнение двух файлов на диске, по форме
суиты. Штаб об этом не просил — решить после основной проверки.

**Status:** open

### #2. Сторона записи: имя из транскрипта — гипотеза, пока его нет в `people:`

**Возникло в:** бриф, причина случая
**Описание:** линтер ловит ошибку после записи. Ошибку делает сессия, пишущая протокол, и штаб завёл у себя правило:
имя в протоколе, которое пришло из распознавания, — гипотеза. Место такому правилу в навыке встреч — в разделе
разбора встречи, который проектирует [[meetings-parse-section/workitem|meetings-parse-section]] (промпт субагента).
Перенести туда одной строкой при работе над тем кристаллом.

**Status:** open

### #3. Пересказ встречи бывает не только в `index.md`

**Возникло в:** чтение брифа
**Описание:** указатели на встречу в `comms/` треков и записи треков тоже пересказывают, кто что сказал. Бриф
ограничен `meetings/*/index.md`; расширять, только если такой случай придёт.

**Status:** open
