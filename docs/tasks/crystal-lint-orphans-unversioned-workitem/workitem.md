# crystal-lint: в workitem, которого нет в HEAD, каждая правка называет все старые побеги новыми

> Заведён сессией intercom 2026-11-17 по письму агента демо-проекта владельца. Делает основная сессия: сессия intercom
> код не правит, рабочее дерево общее. Письмо пересказано, имён проектов, их кристаллов и людей здесь нет (CLAUDE.md,
> правило 7); адрес письма — в DL #1. Сосед по теме — [[crystal-roots-git-excluded/workitem|crystal-roots-git-excluded]]:
> тот же класс «кристалл вне git», другой механизм (поиск корней).

## Назначение

**Входящее.** В демо-проекте с 2026-11-13 `/docs/tasks/` лежит в `.git/info/exclude` — кристаллы локальные по решению
владельца. 2026-11-17 агент добавил в свой workitem один побег и два пункта Next actions. После каждой из четырёх правок
`PostToolUse`-хук `crystal-lint.sh --hook` (vdm 2.81.1) возвращал блокирующее «Open sidetracks this change introduced
have no checkbox» и перечислял восемь побегов, открытых 2026-10-23..28, которых правки не касались. Агенту остаётся
либо раздать чекбоксы чужим побегам, которые он не разбирал, либо оставить ход заблокированным.

**Готово, когда** правка workitem, которого нет в HEAD, называет только побеги, которых не было до неё; красный тест
в `tests/crystal-lint.test.sh`; выпуск `vdm` (скрипт только в нём — `plugins/vdm/scripts/crystal-lint.sh`, зеркала нет).

## Текущая модель

- **Причина.** `orphans_at_head` в `plugins/vdm/scripts/crystal-lint.sh` (комментарий над ней: «Nothing for a file HEAD
  does not have (new, untracked) or outside git: then every orphan in the file is one this change introduced»). Для
  нового файла это верно. Для файла, который давно лежит на диске и никогда не попадёт в HEAD (исключён через
  `.gitignore` / `.git/info/exclude`, или просто не отслеживается), — ложь, и блокирующая: базы сравнения нет навсегда.
- **Воспроизведено 2026-11-17** в scratchpad сессии на установленном vdm 2.81.1: `git init` без коммитов,
  `{"crystal": {"paths": ["docs/tasks"]}}` (обход соседнего дефекта поиска корней), workitem из шаблона плюс карточка
  `### #1. Old card` со `**Status:** open` без чекбокса; payload `PostToolUse` Edit → `crystal-lint.sh --hook` даёт
  rc=2 и называет `#1. Old card`. Одинаково для файла под `git add` и для исключённого (`git check-ignore -q` — да). В
  фикстуре не было HEAD вовсе; случай письма (HEAD есть, файла в нём нет) идёт той же веткой: `git show HEAD:<path>`
  падает, база пуста.
- **Варианты базы** (выбор — основной сессии, записью в DL):
  - **(a) из письма:** для Edit «до» = текущий файл с обратной заменой `new_string` → `old_string`; MultiEdit — обратные
    замены в обратном порядке. Брать эту базу, когда файла нет в HEAD (исключён или не отслеживается — предикат «нет в
    HEAD», а не «игнорируется»: давно не отслеживаемый файл страдает так же). Write поверх существующего файла — «до»
    не восстановить из payload, если `tool_response` не несёт прежний текст: не проверено.
  - **(b) перенести эту проверку для файлов вне HEAD в `--pre-hook`:** он уже видит файл до правки и сравнивает до/после
    для канона. Цена — семантика: сейчас проверка побегов — совет после правки, а pre-hook правку отклоняет.
- **Соседняя поверхность, не проверено вживую:** `--bash-hook` берёт кандидатов через `git ls-files --others
  --exclude-standard`. Неотслеживаемый неисключённый workitem туда попадает с пустым `before` — тот же ложный список
  после любой команды, назвавшей файл. Исключённый не попадает вовсе — правка через Bash в нём не проверяется ничем
  (молчание, а не ложь; см. Sidetrack #1).

## Sidetracks

### #1. `--bash-hook` не видит исключённые workitem

**Возникло в:** чтение `--bash-hook` при разборе письма, 2026-11-17
**Описание:** кандидаты собираются через `git ls-files … --exclude-standard`, поэтому workitem под `.git/info/exclude`
после записи через Bash не проверяется ни на канон, ни на побеги, ни на завершение. Тот же класс, что поиск корней в
`crystal-roots-git-excluded`. Решить вместе с выбором базы: брать ли исключённые workitem из корней кристаллов, а не
из индекса.
