# Интерком: форма эстафеты — ответ и пересылка без вклейки предыдущего письма

> Побег `comms-plugin` #2 (2026-09-21), вынесенный в свой кристалл при закрытии
> родителя: хвост — единица работы над интеркомом, а не однострочное «потом».
> **Отгружен 2026-09-22 в `vdm` 2.30.0.**

## Назначение

**Цель.** Эстафета `space-hq → global-auth-gap → t23b-program → vdm` дошла как одно письмо
на 64 КБ с двумя уровнями `>`-цитирования: каждый агент вклеивал предыдущее письмо
целиком (§Б содержит §12, §12 — исходник). Маршрут сработал, фактура прибавлялась на
каждом пролёте, но последний получатель читал вложенные цитаты. Нужна форма, в которой
письмо ссылается на предыдущее, а не содержит его.

**Ограничения.** Хранилище вне репозиториев, без состояния; конверт — машинная истина;
`send` не должен усложниться для одиночного письма.

**Критерий успеха.** Агент, продолжающий эстафету, командой вида
`send <to> <slug> --reply-to <slug>` получает письмо, чей конверт указывает на
предыдущее, а получатель видит цепочку и может открыть каждое звено; ни одно письмо не
содержит другого.

## Текущая модель

Отгружено в `vdm` 2.30.0: необязательное поле конверта `reply-to: <identity>/<slug>`,
флаг `send --reply-to <ref>`, строка `↩ **CONTINUES:**` в баннере, вывод цепочки в
`check`, подкоманда `chain <slug>`. Помощники `intercom_find_letter`,
`intercom_letter_ref`, `intercom_chain` в `intercom-common.sh`. 26 тестов, 21 доказан
красным на копии плагина до правки (`INTERCOM_BIN`).

**Замер, определивший форму** (DL #2): один случай эстафеты на 318 писем хранилища.
Вклейку ничто не требовало — хранилище один каталог, инбоксы соседи, предыдущее письмо
читалось по пути. Поэтому копия рядом (`<slug>.prev.md` из наброска) не понадобилась:
недоступным звено бывает только когда его удалили, и это честнее назвать, чем
подменить.

**Чего нет.** Отдельного флага для пересылки: у пересылки и ответа ссылка одна и та же,
различается только `to`, а он уже есть. Списка звеньев в конверте: цепочка выводится
обходом, хранить её значило бы завести состояние, способное разойтись с письмами.

## Decision Log

### #3 / 2026-09-22 / Неразрешимая ссылка — жёсткий отказ до записи файла

**Source:** assistant
**Basis:** derived
**Basis-detail:** тот же закон, что у неразрешимого адресата в `send` («бриф, легший в
инбокс, который никто не читает, выглядит как доставленный»).
**Context:** альтернатива — записать ссылку как есть и разбираться при чтении.
**Why:** письмо, ссылающееся на несуществующее, хуже отсутствия письма: читатель не может
отличить сломанное звено от целого. Двусмысленный голый слаг — тоже отказ, с перечнем
кандидатов.
**Implication:** `--reply-to` резолвится **до** создания файла; при отказе не пишется
ничего. Пропавшее постфактум звено и цикл называются при обходе, а не обрывают его.

### #2 / 2026-09-22 / Форма — адрес, а не копия; цепочка выводится, а не хранится

**Source:** assistant
**Basis:** measured
**Basis-detail:** замер по всему хранилищу — **один случай эстафеты на 318 писем**; тот
самый, 64 КБ, 288 строк цитат из 550. Второго случая нет, то есть решение принималось на
одном специмене, и это записано здесь намеренно.
**Context:** набросок в «Текущей модели» допускал копию предыдущего письма рядом
(`<slug>.prev.md`) «если оригинал недоступен».
**Why:** хранилище — один машинный каталог, инбоксы соседи; оригинал был доступен всегда,
не хватало только формы, чтобы его назвать. Копия не понадобилась бы ни разу, а
сверять её было бы не с чем.
**Implication:** поле хранит `<identity>/<slug>`, не путь (путь устаревает при `pickup`);
цепочка строится обходом ссылок, а не списком в конверте. Записано в `docs/model/suite.md`
→ «Тот же выбор, но про данные: адрес или копия».

### #1 / 2026-09-21 / Выделен из `comms-plugin` #2 при закрытии родителя

**Source:** user

**Basis-detail:** «всё по порядку» — закрытие `comms-plugin` потребовало дать побегу дом;

**Implication:** `ready`; приоритет ниже ломтей `vdm-comms`.
