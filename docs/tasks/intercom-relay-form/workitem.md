# Интерком: форма эстафеты — ответ и пересылка без вклейки предыдущего письма

> Побег `comms-plugin` #2 (2026-09-21), вынесенный в свой кристалл при закрытии
> родителя: хвост — единица работы над интеркомом, а не однострочное «потом». Заведён в
> `ready`; работа не начата.

## Назначение

**Цель.** Эстафета `space-hq → global-auth-gap → t23b-program → vdm` дошла как одно письмо
на 64 КБ с двумя уровнями `>`-цитирования: каждый агент вклеивал предыдущее письмо
целиком (§Б содержит §12, §12 — исходник). Маршрут сработал, фактура прибавлялась на
каждом пролёте, но последний получатель читал вложенные цитаты. Нужна форма, в которой
письмо ссылается на предыдущее, а не содержит его.

**Ограничения.** Хранилище вне репозиториев, без состояния; конверт — машинная истина;
`send` не должен усложниться для одиночного письма.

**Критерий успеха.** Агент, продолжающий эстафету, командой вида
`send <to> <slug> --reply-to <slug>` получает письмо, чей конверт указывает на
предыдущее, а получатель видит цепочку и может открыть каждое звено; ни одно письмо не
содержит другого.

## Текущая модель

- Сегодня в конверте нет поля для ссылки на другое письмо; `to_input` хранит только
  подсказку адресата. Цепочка восстанавливается лишь по тексту.
- Письма живут в инбоксах разных агентов; «предыдущее» лежит у другого получателя (или в
  его `_done/`). Ссылка — это `from` + `slug` + `created`, не путь.
- Вариант формы: поле `reply-to: <from>/<slug>` в конверте; `check` печатает цепочку;
  копия предыдущего письма рядом (`<slug>.prev.md`) — только если оригинал недоступен.
- Не проверено: как часто эстафеты вообще случаются (один случай на 2026-09-21).
