# Публичный репозиторий без чужих данных: чистка дерева, перепись истории, гард против PII

> Повод — сверка 2026-10-01/02 по записке владельца `published-references-third-party` (intercom-хранилище, вне
> репо). Репозиторий публичный, а в нём лежат фамилии реальных людей, ключи задач рабочих трекеров, имена агентов,
> а в метаданных коммитов — рабочий адрес. **Этот файл сам публичный**: здесь только пути, числа и роли; точные
> списки — в приватной записке.

## Назначение

**Цель.** В публичном репозитории и во всей его истории нет:
1. имён и фамилий реальных людей;
2. ключей задач и других идентификаторов рабочих систем;
3. имён конкретных агентов — где для логики взаимодействия важна роль, она так и называется: штаб, программа,
   командный центр, слой доступа;
4. рабочего адреса в метаданных коммитов.

Плагин нейтрален: примеры вымышленные (Петров, John Doe, `PROJ-123`, `example.com`), любой агент может оказаться на
любой роли. И это держит системный гард, а не память.

**Ограничения.** Перепись истории необратима для публичного репозитория: новые хеши у всех коммитов, force-push на оба
remote, и это делает владелец. Список замен в репо не попадает — иначе он сам публикация. Хеш-ссылки в письмах агентов
(вне репо) останутся старыми — принято владельцем (DL #1).

**Критерий успеха.** Детектор этого кристалла по всей переписанной истории даёт ноль находок на эталоне сверки;
новый коммит с такими данными гард не пропускает; в метаданных один автор — `Dmitry Vorobyev <dmitry@vorobyev.org>`.

## Decision Log

### #1 / 2026-10-02 / Переписать историю, а не только почистить дерево или скрыть репозиторий

**Source:** user
**Basis:** user-stated
**Basis-detail:** владелец, прочитав цитаты с файлами: «Да, это наш недосмотр тут. Плагин должен быть максимально
нейтральным… Нам придется навести порядок и да переписать коммиты». О сломанных ссылках в письмах: «интерком не
должен идти в репозиторий же».
**Context:** варианты — чистка одного дерева; приватный GitHub (хеши целы, нужна смена источника автообновления на
SSH); перепись с force-push; и то и другое.
**Why:** данные уже в истории публичного репо; чистка дерева их оттуда не убирает, приватность — меняет сам
характер репо.
**Implication:** фазы в «Next actions»; force-push — руками владельца после проверки детектором.

### #2 / 2026-10-02 / Плагин нейтральный: вымышленные примеры, агенты — по роли

**Source:** user
**Basis:** user-stated
**Basis-detail:** «Имена абстрактные. Петров, John Doe и т.д.»; «Упоминания агентов - не должно тоже быть. Любой
агент может быть. Можно как-то описать если это важно типа hq, program, command center и т.д. если это касается
какой-то логики взаимодействия между.»
**Context:** люди и ключи — очевидно; агенты — нет: это имена репозиториев владельца, но часть указывает на рабочие
проекты, а поставляемый код ссылается на них как на источник находки («Field case (<agent>, <date>)»).
**Why:** плагин работает с любым набором агентов; имя конкретного делает текст частным и выдаёт окружение.
**Implication:** замены — люди на вымышленных, ключи на `PROJ-123`, агенты на роль или просто «агент». Решение
«штаб — через реестр, по имени слоя доступа» (`vdm-comms-outward-checks`, DL #5) переходит на роль. Правило
записать там, где его прочтут при авторстве (Next actions, фаза A).

### #3 / 2026-10-02 / Один автор во всей истории

**Source:** user
**Basis:** user-stated
**Basis-detail:** «dmitry@vorobyev.org - легитимен. Остальные - да тоже надо причесать.» Замер: в истории три
подписи — рабочий адрес (408 записей), `dmitry@vorobyev.org` под двумя написаниями имени (12 и 6).
**Context:** перепись меняет хеши всё равно; заодно приводятся и метаданные.

**Implication:** `--mailmap` в переписи; локальный конфиг репо переключён сразу, чтобы новые коммиты до переписи не
добавляли записей.

### #4 / 2026-10-02 / Системный гард против PII на готовой библиотеке

**Source:** user
**Basis:** user-stated
**Basis-detail:** «И потом построить нормальный гард который это не будет допускать. Есть готовые библиотеки чтобы
не пропускать PII. ДАвай прикрутим. Если надо - подключим JEV на этапе коммита например. Но точно нужно системное
решение.» Не проверено: какая библиотека берёт русские имена в смешанном русско-английском тексте и с какой
точностью; где исполняется Jev и уходит ли проверяемый текст во внешний сервис.
**Context:** вето в скиле — мягкое и не сработало шесть раз; список имён в публичном гарде сам был бы публикацией.
**Why:** обнаружение без списка: NER для имён, распознаватели по образцу для ключей, `[~login]`, адресов.
**Implication:** фаза B; детектор заодно — приёмочный тест переписи.

### #5 / 2026-10-02 / Порядок: правило и гард, затем дерево, затем перепись

**Source:** assistant
**Basis:** inferred
**Basis-detail:** выведено из устройства `filter-repo` (замена строк во всех версиях файлов за один проход) и из
того, что детектор проверяет результат по всей истории. Не проверено: точность детектора на этом репо — до неё
порядок держится на рассуждении.
**Context:** можно переписать сразу, а гард поставить потом.
**Why:** перепись делается один раз; всё, что попадёт в дерево до неё, перепишется вместе. Гард, стоящий до
переписи, не даёт новым коммитам добавлять то, что перепись убирает, и даёт ей приёмочный тест.
**Implication:** фазы A → B → C → D → E.
