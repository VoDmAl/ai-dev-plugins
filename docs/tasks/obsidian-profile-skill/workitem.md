## Назначение

**Цель.** Из сессии **любого** репозитория с vault'ом пользователь говорит «у меня тут не
все актуальные настройки Obsidian» — и ассистент знает, куда идти за эталоном, что
запустить и в каком порядке. Сегодня инструмент существует, но живёт внутри одного
vault'а и в чужих сессиях не обнаруживается никак.

**Ограничение.** Логику не переписывать. Merge-политика ключей, резолв плагинов и
таблица дефолтов Obsidian живут в коде vault'а и меняются там. Skill их **зовёт**.

**Критерий успеха.** Приёмка на живой фикстуре `/Users/vdm/AI Projects/global-auth-gap`:
пользователь открывает там сессию, произносит фразу про настройки, skill сам находит
эталон, показывает дрейф, объясняет гейт открытого vault'а, применяет по согласию,
`check.mjs` возвращает 0.

**Входящий контекст.** Интерком-бриф `obsidian-profile-skill` от `obsidianvault`
(2026-09-08), продвинут сюда через `pickup --grow`. В том же инбоксе лежит **второй,
более ранний** бриф `obsidian-hygiene-plugin` (2026-09-06) — он остаётся `pending` и в
объём этого кристалла не входит (DL #1), но частично с ним пересекается (Sidetrack #3).

## Текущая модель

**Что уже готово и не переписывается.** `/Volumes/Working/ObsidianVault/projects/vault-profile/`
— Node без зависимостей, четыре скрипта (`check.mjs`, `apply.mjs`, `reference-drift.mjs`,
`plugin-settings-diff.mjs`), пресеты слоями `base` → `repo-docs` | `kb`, реестр целей
`presets/targets.json` (8 целей, поле `reference` указывает на сам эталон).

**Что скрипт умеет, проверено запуском** (не по документации):

| | |
|---|---|
| запуск из чужого cwd | работает по абсолютному пути к скрипту; `targets.json` резолвится от расположения скрипта, не от `pwd` |
| exit 0 | расхождений нет |
| exit 1 | есть расхождения **или** каталога нет — одним кодом |
| каталог без `.obsidian/` | **не отказ**: 29 расхождений и предложение `apply` |

**Форма v1.** Skill `obsidian-profile`, шесть шагов: распознать симптом → найти эталон
(громко упасть, если тома нет) → определить целевой vault (и убедиться, что это vault) →
`check` → показать план `apply` → по согласию `--apply` → напомнить переоткрыть.

**Что в этот кристалл не входит.** Сводный проход `--all` по всем восьми целям и строка
«1 из 8 отстали» — это утверждение о парке репозиториев, оно уезжает в `vdx` (DL #3).

**Где живёт.** Новый плагин `plugins/vdm-obsidian/` (DL #7), skill вызывается как
`/vdm-obsidian:profile`. Путь эталона — `~/.claude/vdm-plugins.json` →
`obsidian-profile.reference`, дефолт `/Volumes/Working/ObsidianVault` (DL #6).

**Оба блокирующих вопроса закрыты; открытым остаётся один технический** — два из пяти
pre-commit гейтов захардкожены на два плагина и третий их молча сузит (Sidetrack #6).
Решить до первого коммита нового плагина.

### #3. Правила 9–11 из hygiene-брифа — предмет ЭТОГО кристалла, а не того

**Status:** open
**Возникло в:** разбор двух брифов рядом.

Инвентарь `obsidian-hygiene-plugin` перечисляет 11 правил на вынос. Три из них —

первого брифа: не покрыты ли они уже пресетом `base`/`kb` — тогда из инвентаря выносим,
а не переносим. Отдельно: `apply.mjs` **намеренно не переносит плагинные `data.json`»
(шапка скрипта: там пути и 32 КБ пинов эталона), а правило №10 — как раз про `data.json`;
значит оно в профиль не укладывается вовсе и остаётся правилом.

### #5. Плагин ставит skill, инертный на любой другой машине

**Status:** open

### #6. Два pre-commit гейта из пяти захардкожены на два плагина

**Status:** open
**Возникло в:** проверка последствий DL #7 — что тянет за собой третий плагин.

- `scripts/check-lib-sync.sh` (строки 10–11) держит ровно две переменные, `VDM_LIB` и
  `VDM_GIT_LIB`. Появись у `vdm-obsidian` свой `lib/` — он для зеркального инварианта
  невидим и разойдётся молча.
- `scripts/check-skill-paths.sh` обходит `plugins` целиком (`find plugins -type f`), но
  сам паттерн на строке 53 — `plugins/(vdm|vdm-git)/(scripts|lib|hooks|templates|skills)/`.
  Утечка dev-пути вида `plugins/vdm-obsidian/scripts/foo.sh` в новом `SKILL.md` не будет
  поймана.
- `scripts/check-version-bump.sh` — обходит `plugins/*/` в обеих фазах (строки 78 и 132),
  третий плагин подхватит сам. Чинить не нужно.

Это ровно тот анти-паттерн, который репозиторий уже разобрал в
`docs/llm/soft-guidance-vs-deterministic-gates.md` — гейт, считающийся проволоченным,
пока не проверишь, что он покрывает. Два варианта: обобщить оба гейта на `plugins/*/`,
либо явно решить, что `vdm-obsidian` не заводит `lib/` (тогда чинить только второй).
Решить **до** первого коммита нового плагина, иначе гейт молча сузится и никто не заметит.
