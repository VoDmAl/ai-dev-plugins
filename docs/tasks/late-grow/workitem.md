# Кристалл заводится до первого решения, а не по вопросу владельца

> Вырос из брифа агента машин (21.10): работа на несколько дней шла без кристалла, пока владелец не спросил «Мы в
> кристалле работаем, да?». Бриф пересказан, не скопирован; адрес — в DL #1.

## Назначение

Полевой случай агента машин, 2026-10-21, одна сессия. Вопрос владельца о критической уязвимости перерос в работу на
несколько дней: обновления на двух серверах, автообновление сторонних репозиториев, пауза контейнеров в бэкапе, переезд
одной службы, письма агентам двух проектов. Кристалл появился только после вопроса владельца. К тому времени git-guard
подготовил три коммита, а 11 записей Decision Log и 10 побегов пришлось восстанавливать задним числом из чата.

Сигналы навыка срабатывали, и не один. Первый ответ кончался двумя вопросами владельцу. Второй был планом из пяти
шагов с четырьмя вопросами и тремя решениями. В рассуждении агент записал «кристалл нужен, заведу на шаге реализации»,
а факты положил в автопамять проекта. Решения дальше приходили ответами на нумерованные вопросы («1. Да 2. … 4.
Окей»). Заведённый кристалл агент назвал по текущему шагу, и владелец поправил имя на задачу.

Цель — чтобы кристалл заводился до первого решения. Критерий: по каждому из шести предложений брифа решено, берём ли
и куда (описание навыка, тело навыка, хук, общий слой правил, `vdx`), или отказ с причиной; ответ агенту машин ушёл.

Предложения брифа:
1. Антипаттерн «заведу, когда дойдём до X»: такая фраза в рассуждении и есть grow, сейчас.
2. Антипаттерн «память вместо кристалла»: запись в автопамять фактов текущей работы — сигнал grow.
3. Сигнал «владелец отвечает на нумерованный список вопросов» — каждый ответ уже запись в Decision Log.
4. Оговорка про инцидент: срочность не повод откладывать; минимум — скелет в первые минуты.
5. Имя по задаче, а не по шагу: «что закрывает этот кристалл?»
6. Механика без активного кристалла: Stop-хук смотрит последнее сообщение (≥5 шагов или ≥2 вопроса владельцу), или
   счётчик «git-guard подготовил N коммитов, а ни один `workitem.md` не тронут».

## Текущая модель

- **Навык уже знает все эти сигналы** (`plugins/vdm/skills/crystal-grow/SKILL.md`, 2026-10-21): фразы (1), рефлекс
  шага 0 (2), форма плана ≥5 шагов / ≥3 решения / ≥2 вопроса (3), контекст на 50% (4), рефлекс пути (5). По словам
  брифа, у агента сработали (2) и (3).
- **Но тело навыка грузится только при вызове.** До вызова сессия видит одну строку описания: «Invoke when a session
  is widening into research, brainstorm, PRD work, or any flow likely to spawn 3+ branches». О «до первого решения»
  в ней нет ни слова. Бриф говорит, что в контексте была только эта строка; это его слова, не проверено.
- **Без активного кристалла не напоминает ничего** — проверено в коде 2026-10-21. `crystal-capture-reminder.sh`
  выходит молча при `[ -z "$active" ]`. `crystal-stop-reminder.sh` выходит, когда нет активного кристалла с открытыми
  пунктами и нет неканоничных статусов. `crystal-hydrate.sh` при старте называет только существующие кристаллы. Чем
  больше работы идёт вне кристалла, тем тише вся механика.
- **Случай брифа не единичный** (DL #3): с 15.09 из 116 рождений кристаллов 8 начаты просьбой владельца, в двух — с
  причиной «чтобы не забыть» и «чтобы не потерялось при сжатии». Это нижняя граница.
- **Активных кристаллов три** (режим по умолчанию — один на репозиторий): `rules-dream`, `intercom-session-wake`
  параллельной сессии и этот. См. DL #2.

## Decision Log

### #1 / 2026-10-21 / Кристалл заведён сразу, до разбора предложений; имя по задаче

**Source:** both
**Basis:** user-stated
**Basis-detail:** владелец на вопрос «Заводим под бриф агента машин кристалл сразу?» выбрал «Да, late-grow
(Recommended)». Бриф — письмо `crystal-late-grow-incident` в intercom-ящике ai-dev-plugins (21.10, 19:01Z), вне
репозитория; пересказан выше по ролям, потому что репозиторий публичный.
**Context:** бриф предлагает шесть изменений, одно из них — новый механизм. Это работа на несколько шагов с решениями
по каждому пункту.
**Why:** разобрать предложения в чате и завести кристалл потом значило бы повторить ровно то, о чём бриф. Имя —
по задаче, которую кристалл закрывает (кристалл заводится вовремя), а не по первому шагу.
**Implication:** разбор каждого предложения — запись в этом Decision Log; ответ агенту машин — пункт Next actions.

### #2 / 2026-10-21 / `rules-dream` остаётся активным, хотя активных станет три

**Source:** assistant
**Basis:** observed
**Basis-detail:** `.claude/vdm-plugins.json` → `crystal` пуст, значит один корень и режим «один активный на
репозиторий». `plugins/vdm/scripts/crystal-hydrate.sh` считает просроченные сроки (`count_overdue`) только у
активных кристаллов. У `rules-dream` пункт `(due: 2026-10-27)`.
**Context:** чек-лист навыка просит перевести остальные активные кристаллы в `dormant` перед grow. `intercom-session-wake`
— кристалл параллельной сессии, его не трогаю. `rules-dream` ждёт до 27.10 и сейчас работы не требует.
**Why:** в `dormant` у `rules-dream` пропал бы при старте сессии сигнал о просроченном сроке. Это именно тот
механизм, который должен напомнить о 27.10. Нарушение инварианта видно при старте и стоит одной строки, а потерянный
срок — пропущенное обязательство.
**Implication:** три активных до закрытия одного из них. Само молчание сроков у спящих кристаллов — Sidetrack #1.

### #3 / 2026-10-21 / Владельцу приходится просить кристалл примерно в одном рождении из 14 — случай брифа не единичный

**Source:** assistant
**Basis:** observed
**Basis-detail:** разбор транскриптов в `~/.claude/projects` на lft 2026-10-21, сессии с 15.09. Рождение кристалла —
вызов `/vdm:crystal-grow` или `Write` нового `tasks/<slug>/workitem.md`, без повторов по сессии и ходу: 116. В двух
ходах владельца перед рождением слово «кристалл» есть в 22. Разобраны руками. 8 начаты самим владельцем без видимого
предложения ассистента: «Но сначала кристалл чтобы не потерять…», «Создавай кристалл по всем находкам», «Давай в
кристалл и запустим… параллельную сессию», «Давай кристалл сделаем… чтобы ничего не потерялось при сжатии
контекста», «Все по очереди заведи кристалл чтобы не забыть», «Оформляй в кристалл…», «давай это в кристалл добавим и
рассмотрим по одному», «ДА, но не сразу, а в кристалл». 3 — «да» владельца на предложение ассистента. 11 не про
рождение («продолжаем кристалл X»). Не проверено: случаи, где владелец просил раньше двух ходов (случай брифа так и не
пойман), и сессии, где кристалл был нужен и не родился вовсе. Скрипты замера — во временном каталоге сессии, метод
пересказан здесь.
**Context:** механизм из предложения 6 — новый хук. На одном полевом случае его не обосновать.
**Why:** 8 из 116 — нижняя граница: окно в два хода пропускает поздние просьбы, а несостоявшиеся рождения не видны вовсе.
Сам признак устойчив: владелец словами делает работу сигнала («чтобы не забыть», «чтобы не потерялось при сжатии»).
Первый грубый срез (коммиты git-guard до первой правки кристалла) отброшен: в многотемной сессии ранние коммиты
относятся к прошлым темам и не говорят о позднем кристалле.
**Implication:** у предложения 6 есть основание сильнее одного случая. Каким должен быть сигнал — следующий пункт:
разбор шести предложений.

## Sidetracks

### #1. У спящего кристалла срок молчит

**Возникло в:** DL #2
**Описание:** `crystal-hydrate.sh` показывает «⏰ ПРОСРОЧЕНО» только у активных кристаллов. Кристалл, переведённый в
`dormant` по требованию инварианта «один активный», теряет сигнал о своих сроках, а пауза — как раз то состояние, в
котором срок легче всего пропустить. Инвариант и сигнал срока тянут в разные стороны. Кандидат: при старте одной
строкой называть просроченные сроки и у спящих кристаллов. `/vdm:crystal-cave` показывает их и сейчас, но его зовут
руками.

**Status:** open
