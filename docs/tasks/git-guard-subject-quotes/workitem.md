# git-guard: тема коммита в примерах — в одинарных кавычках

> Заведён сессией intercom 04.11 по брифу агента сайта: тема коммита с `$20` в
> двойных кавычках потеряла `$20`. Код не тронут; правка — для основной сессии
> владельца.

## Назначение

Каждый пример вызова `git-guard-prepare` — в напоминании git-guard, которое приходит
с каждым промптом, в `vdm-git:guard`, в `vdm:wrap`, в usage самого helper'а — передаёт
тему в двойных кавычках: `git-guard-prepare "<subject>"`. Ассистент повторяет форму, и
оболочка (Bash-инструмент запускает zsh) подставляет в теме `$…` и `` `…` `` до того,
как helper её увидит. Helper получает уже испорченную строку и заметить этого не может.

Готово, когда ни один пример не учит двойным кавычкам, а тема с апострофом имеет
названный безопасный путь.

## Текущая модель

- Дефект — в форме примера, не в helper'е (DL #1). Одинарные кавычки останавливают
  и `$…`, и обратные кавычки; апостроф внутри них невозможен — для такой темы у
  helper'а уже есть чтение из stdin (`git-guard-prepare -`) с heredoc в кавычках.
- Места, где пример в двойных кавычках (04.11): `plugins/vdm-git/scripts/git-guard-reminder.sh:158`
  (дважды), `plugins/vdm-git/scripts/git-guard-hook.py:502`, `:543`,
  `plugins/vdm-git/skills/guard/SKILL.md:123`, `:261`, `:553`, `:668`,
  `plugins/vdm/skills/wrap/SKILL.md:132`, `plugins/vdm-git/bin/git-guard-prepare:9`, `:10`, `:692`.
  В одинарных — ни одного.
- Страховка в helper'е (предупреждать, если тема кончается запятой или пробелом) —
  не решена: см. Next actions.

## Decision Log

### #1 / 2026-11-04 / Тема съедается оболочкой до helper'а: чинить пример, не helper

**Source:** both
**Basis:** observed
**Basis-detail:** Воспроизведено 04.11 в сессии intercom: `zsh -fc 'print -r -- "[+] Price on the new date, $20|"'`
печатает `[+] Price on the new date, |` — zsh читает `$20` как двадцатый позиционный
параметр; bash печатает `…, 0|` (`$2` и «0»). Бриф описывал механизм bash, исход в поле —
zsh. Счёт по этому репозиторию (`git log --format=%s`, 04.11): 392 темы, из них со `$` — 2,
с обратной кавычкой — 4, с апострофом — 1. Бриф агента сайта —
`intercom: ai-dev-plugins/_done/git-guard-prepare-subject-quotes.md` (вне репозитория;
пересказан, не скопирован — письмо другого агента, тема из чужого репозитория заменена
вымышленной).
**Context:** Бриф предлагает писать пример в одинарных кавычках и, как страховку, чтобы
helper предупреждал о теме, которая кончается пробелом или запятой — частом следе
съеденной подстановки.
**Why:** Helper получает аргумент после подстановки и отличить испорченную тему от
задуманной не может; править нужно ту форму, которую ассистент копирует. Одинарные
кавычки закрывают обе подстановки, причём обратная кавычка в двойных опаснее `$`: она
не стирает текст, а выполняет команду. Цена — апостроф (1 тема из 392); для него путь
уже есть, `git-guard-prepare -` со stdin, и его остаётся назвать рядом с примером.
**Implication:** Правятся тексты примеров во всех местах из «Текущей модели»; helper
без изменений, кроме возможной страховки — она решается отдельно.
