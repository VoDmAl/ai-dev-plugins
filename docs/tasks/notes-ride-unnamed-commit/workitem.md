# Записки едут «со следующим коммитом», которого нет: правило слоя и проверка у ветки без будущего

> Бриф агента одного рабочего проекта (10.11, адрес в References). Владелец там: «может стоит передать фактуру в vdm
> skill агента? Это не только тут такая ерунда». Заведено сессией intercom как парковка для основной сессии; правило слоя
> ждёт слова владельца.

## Назначение

Агент держит готовые записки (кристалл, заметки) незакоммиченными и пишет, что они «уйдут со следующим коммитом», не
называя этот коммит, а его часто не будет. Чинить в двух местах:

1. **Правило общего слоя** (`~/.claude/vdm/rules.md`, «Make the moves your tools reach; hand the user only theirs,
   prepared», последняя фраза: «bookkeeping rides the next real commit or one at session end»). Записки ждут следующего
   коммита, только если его можно назвать; иначе они идут отдельным коммитом сейчас или в конце сессии. Ставит
   `rules-write.py` по слову владельца (`/vdm:learn`, шаги 1–4).
2. **Проверка в момент, когда коммита уже не будет**: незакоммиченные записки на ветке, upstream которой `[gone]`, или
   MR которой вышел из Draft или слит. Называть их и предлагать отдельный коммит с записками сейчас.

Критерий успеха: первый абзац правила в слое ставит условие «коммит, который можно назвать», и сессия получает его на
старте. В момент, выбранный по DL, записки на ветке без будущего названы. Отправитель получил место правила и версию и
снял две записи из памяти своего проекта.

## Текущая модель

- **Правило установлено 10.11 в 19:53Z** по слову владельца (DL #2). В конце правила «Make the moves your tools reach…»
  теперь: «Commits, sends, comments go one per change readers need, prepared the turn it is done and checked; bookkeeping
  rides the next one only if you can name it (same branch or thread, work already planned), else goes alone now or at
  session end. A change under someone's review grows by additions (a new commit, plain push, a new comment); rewrite it
  (amend, force-push, edit) only while it is a draft.» Предыдущая версия: `~/.claude/vdm/history/rules-20261110T195333Z-c46665af.md`.
  Слой 8271 из 9000 байт (`shared-rules.sh --measure`), выше 8100: глубокий проход назначен письмом `rules-deep-pass-due-6`.
  Первый итог ушёл отправителю (`notes-ride-unnamed-commit-outcome`), его мяч — снять две записи из памяти своего проекта.
  Наша часть — проверка у ветки без будущего.
- **Три случая из брифа, все в одном рабочем проекте:**
  1. 03.11: готовая проверенная правка кода ждала «один amend потом, вместе с ключом задачи и rebase».
  2. 06.11: правки только в кристалле ждали «следующего рабочего коммита».
  3. 10.11: MR вышел из Draft и финальный, кода в ветке больше не будет. В основную ветку владелец пушить не может
     (репозиторий чужой), ветка исчезнет после слияния. Агент написал, что правки кристалла «уйдут со следующим коммитом
     кода». Владелец: «С каким кодом они уйдут? С чужим?»
- **Память того проекта пересказала правило** как «no notes-only commits/pushes (rules layer, 22.10)», и вторая ветка
  («or one at session end») потерялась. Это слова брифа, файл памяти не читали. Sidetrack #1.
- **wrap уже коммитит один раз в конце** (шаг 5, «One commit, at the end») и в шаге 1 читает незакоммиченное. Случай 3
  был не в wrap, а в обычном ответе после выхода MR из Draft. Проверка только в wrap его бы не поймала.
- **Признаки «после ветки коммита не будет».** `[gone]` у upstream читается локальным git (`git branch -vv`). Состояние
  MR (Draft, слит) лежит во внешней системе, доступ к ней идёт через echelon, плагин сам туда не ходит.
- **Та же форма в этом репозитории**: 39 незакоммиченных папок кристаллов в `docs/tasks/` (git status 10.11), `created:`
  с 30.10 по 10.11. Sidetrack #2.

### #1 / 2026-11-10 / Правило — через learn по слову владельца; проверка — кристаллом для основной сессии

**Source:** assistant
**Basis:** observed
**Basis-detail:** бриф прочитан целиком. Правило «Make the moves…» прочитано в `~/.claude/vdm/rules.md` 10.11 (отпечаток
`058056d7…fa80`). В 2.79.1 прочитаны `plugins/vdm/skills/learn/SKILL.md`, шаги 1–6 (изменение первого абзаца даёт exit 1
у `--diff`, ставить только по «install?» владельца), и `plugins/vdm/skills/wrap/SKILL.md`, шаги 1 и 5. Кандидат собран
субагентом по `fold-lesson.md` в лёгком режиме, `--diff` запущен, exit 1. Память отправителя не проверялась.
**Context:** бриф просит правило и, по усмотрению, проверку в wrap. Сессия intercom отвечает и делает малое. Код она
оставляет основной сессии, а её панель никто не читает. Прецедент: правило о файлах в чате, 06.11, кандидат и `ask`
через сессию отправителя.
**Why:** правило — одна фраза слоя, и путь у неё готовый: кандидат, `--diff`, вопрос владельцу через сессию, где он был,
установка. Проверка меняет скил и, возможно, хук. Ей нужно своё решение: где проверять (wrap, старт сессии или оба) и
откуда брать состояние MR. Это работа основной сессии со своим критерием.
**Implication:** письмо отложено с заметкой до ответа владельца. Правило ставит сессия, которая получит ответ. Проверку
делает основная сессия по этому кристаллу. Итог отправителю идёт двумя письмами: после установки и после проверки.

## Sidetracks

### #1. Пересказ правила слоя в памяти проекта расходится с оригиналом

**Status:** open

Память отправителя сжала правило до «no notes-only commits/pushes» и потеряла вторую ветку. `learn` шаг 5 делает запись
памяти указателем (`shared: rules.md → <heading>`), но запись, написанная мимо `learn`, остаётся пересказом и расходится с

Сначала пройти линзу из CLAUDE.md: утверждение о памяти каждого проекта — скорее сторона `vdx`.

### #2. 39 незакоммиченных кристаллов в этом репозитории

**Status:** open
**Возникло в:** git status на старте сессии intercom 10.11.

Сессии intercom заводят кристаллы и оставляют себе записку «не закоммичены», коммит делает основная сессия. Коммит назван,
но не наступает: 39 папок с 30.10, у старейших 11 дней. Решить, держит ли записка-себе этот коммит или новому правилу нужен
другой носитель для сессии intercom, которой коммитить нельзя (рабочее дерево общее).
